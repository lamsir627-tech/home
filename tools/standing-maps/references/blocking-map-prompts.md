# 起始站位图提示词

每个 30 秒组都要有一份**起始角色站位图提示词**，供用户生成站位参考图。首轮交付时与人物场景道具提示词一起交付，第二轮用回传的图片约束最终提示词。本页规定内容、沿用规则和编译方式。站位事实来自[站位台账](blocking-ledger.md)，不另起一套口径。画幅与视角遵守本项目已确认要求；旧任务默认的1:1正俯视不覆盖实际场景视角的项目约定。

## 1. 内容要求

- **覆盖全部人物**：图里必须包含该组 30 秒内出现的所有人物，包括可见的画外对手和群演群体。
  - 每人写起始站位、姿态和身体朝向。
  - 组内稍后才入场的人物也要画，放在他们入场的位置，并写明“第几镜入场”。
  - 只有声音的人物（电话声、VO、画外广播）不画，在台账段里登记为 `voice_only`。
- **起始状态**：取每个场景段的入态，不提前放入组内动作完成后的结果。
- **一组多场景**：一组跨多个场景时，每个场景段各出一张图（编号带 `-S入场镜号`），组索引里同时列出。
- **固定方位**：同一地点所有图的方位描述必须相同，例如“图上方为店墙，下方为街面，左为街口端，右为巷深端”。图的方位不随机位变化，也不随画面左右翻转。
- **固定陈设**：写出影响站位判断的固定物，例如门、窗、桌、炉、车，不写与站位无关的杂物。
- **风格与视角**：旧任务默认写实正俯视，与场景资产一致，地面不加文字和箭头；用户需要时可改用平面示意图（圆形标记、朝向箭头、中文名）。默认画幅为1:1，可显式指定其他画幅。实际场景图使用下文的 `--view scene --camera 已登记机位ID`，按台账机位的物理位置、方向和景别出图，不强制正俯视。
- **负面**：每张图都约束人数与名单不符、位置互换或镜像、面部特写、名单外路人、陈设移位、乱码文字；“透视或侧视”仅在正俯视模式排除，不得加入已确认的实际场景视角提示词。

### 原图人物标注

- 站位图生成或回传后，直接在同一张原图上叠加标注。保留原场景、人物、站位与构图。红框和姓名属于成图后的标注层，底图提示词继续要求地面无文字；不得用另贴角色卡、拼贴人物或另画示意图代替原图标注。
- 每个能看到的人都单独用一个红色矩形框圈选实际可见身体。框内顶部用清晰红字写姓名，可加白底字条提高对比度。人物相邻或遮挡时，检查各框不会把另一人的头部误认成对应人物，姓名不得被框线或字条裁切。纯空镜无需加框。
- 对照剧本名单、站位台账和定稿角色或群像图，逐框复核身份、名称和实际人数。无姓名且已确认身份的群演沿用台账称谓或编号。无法可靠辨认时用画面位置或外观标注，并说明待核项；有缺人、多出人物或错列时记录差异，不凭预期名单硬贴姓名。
- 在用户指定的画布交付时，将标注版按场景和镜头顺序放回对应站位图位置，并回读核对图片、顺序与人数。已有成图时，标注本身只需处理原图像素上的叠层。

## 2. 沿用规则

相邻组（或同组内的回切段）属于同一场景实例，且起始站位**没有较大变化**时，沿用同一张图，不重复出提示词。

**较大变化**是指以下任一项发生了变化：
- 人物增减，包括稍后入场的名单；
- 任一人物的站位点；
- 姿态（站、坐、蹲、跪、倒地等）；
- 身体朝向。
- 左右手占用、持物、必要接触或支撑状态；包括稍后入场人物的这些入态和入场镜号。
- 已登记的人物 `look` 或对应身份/衣装资产版本。

仅视线或小表情变化通常可复用，不因每个眼神重新出图；必要的朝向、左右手、承力接点和持物仍须成立。不能将“脚点未变”当作换掌撑地、抓衣角与抓袖等入态相同。图像与台账必要事实冲突时，按当前项目标准标清受影响项并返修；新建图提示词不等于自动授权生图。

不相邻的组即使站位相同，也新建一张图，避免中间插入的场景打乱用户的图片对照。

## 3. 编译

站位图提示词由脚本从台账编译，不手写：

```text
python -B <skill目录>/scripts/build_blocking_maps.py --ledger <工作目录>/scene-state.json --storyboard <结构稿或成品.md> --markdown <交付目录>/站位图提示词.md --json <工作目录>/blocking-maps.json --report <工作目录>/blocking-map-check.json
```

旧任务不加新参数时仍输出1:1正俯视；只指定 `--aspect 16:9` 只改变画幅。项目采用16:9实际场景视角时，显式增加：

```text
--aspect 16:9 --view scene --camera C1
```

`C1` 必须是各相关地点 `locations.<ID>.cameras.C1` 中已登记的机位，并具有 `desc`（物理位置、朝向及需要的景别）；缺失时报告 `scene_camera_missing`，不臆造机位。不同地点机位ID不同时分批选择相应机位。实际场景模式采用真实站位点标签，不把正俯视 `slots.*.plan` 的图上方、下方等坐标直接当成当前机位的画幅方位；空间方位基准另行标明，画面左右须依据实际机位核对。`diagram` 保留为正俯视示意图模式，不能与 `--view scene` 混用。

- **台账要求**（启用站位图时）：
  - 登记每组**所有出场人物**，不只核心人物；所有场景实例都要登记，包括机场、车内这类只出现一次的场景。
  - 地点写 `plan.orientation` 和 `plan.fixed`。
  - 站位点写成 `{"label": "...", "plan": "图中位置"}`。
  - 顶层 `cast` 记录每个人物的 `look`，即一句便于俯视辨认的服装、发型描述，与人物资产一致。
  - 沿用台账已有状态字段 `left_hand`、`right_hand` 和 `contact`：前两者记录占用与持物，`contact`记录其他必要接触和地面、床面、椅面等支撑。没有登记的值省略，不自动补“空手”或承力方式；本编译器不新增独立的 `support`/`holding` 台账字段。
  - 编译器输出已登记的左右手、接触与支撑，并将这些入态、后入场阶段以及 `cast` 中的形象/资产版本信息加入复用签名；不把不同衣装阶段写成同一固定 `cast` 版本后期待工具自动区分。衣装版本仍按项目资产记录管理，换版须重新编译并核对适用范围。
- **检查项**：每个分镜组都有站位图；分镜组“主要主体”里出现的 `cast` 人物，都在该组的图上或已登记为 `voice_only`；每个地点都有方位说明。缺少 `plan` 的站位点会给出警告，此时图上只写站位点名称。
- **输出**：
  - Markdown 文件：组与站位图对照表，以及每张图的完整提示词；
  - JSON 文件：供第二轮绑定使用；
  - 校验报告。
- **退出码**：`0` 通过，`1` 内容失败，`2` 输入错误。

脚本只能覆盖台账里登记过的人物。脚本通过，不代表回传的图片画对了；图片要在第二轮实际查看后核对。

## 4. 与其他规则的关系

- **改了站位就要重新编译**：站位台账一旦修订，就重新编译站位图，并标出受影响的组。用户已回传的旧图对受影响的组失效，需要重新生成，或经用户确认后按图反写台账。
- **第二轮的约束**：最终提示词每组首镜的站位，必须与该组起始站位图一致。见[两轮交付](two-round-delivery.md)。
- **渲染镜头不受影响**：首次登场、冲突顶点的渲染镜头，不改变图里的起始站位。
