# 站位台账与回场卡

起草或修订任何会被后续组再次消费的场景实例前读取本页，包括同组多场、跨组、跨集和隔组回场。本页把[整本模式第3节](full-script-mode.md#3-全剧共用资料与连续场景状态)的实例交接链落成一份机器可核对的 `scene-state.json`，并规定站位文字从台账编译，而不是凭记忆重写。语义判断仍按第3节和[镜头复核 Audit 2B](review-mechanisms.md#audit-2b-scene-state-handoffs-including-nonadjacent-returns)执行，本页不替代它们。

## 1. 为什么必须用台账

隔组回场失控通常有三种原因：执行者读了相邻组而不是同一实例的最近末态；从场景母版或组头记忆中恢复了初始站位；换机位后重新心算画面左右时推错。台账针对这三点：

1. 后续段的入态由脚本从**同一实例上一段的末态**推导，执行者不手写入态；手写时须与推导结果一致。
2. 每次站位、朝向、视线或持物变化都登记承载镜和依据，没有登记的变化等于没有发生。
3. 机位与画面左右来自预先建立的机位表，执行者查表，不在每镜重新心算。

## 2. 文件位置与写入者

`scene-state.json` 放在剧本项目的工作目录（例如 `work/control/states/scene-state.json`），不放进 skill 目录。总控或单窗口执行者是正式台账的唯一写入者；分集执行者在自己的输出目录提交台账候选段，由总控核对后合入（见[分集聊天调度](episode-chat-orchestration.md)）。专项表演/视觉角色不写台账，只在回执中给出头向、视线、手部等状态差量。

台账只存物理站位状态。知情、伤势、衣装、道具资产版本等跨场持续事实继续按现有记录管理，不塞进本文件。

### 启用起始站位图时的额外要求

两轮交付默认启用[起始站位俯视图](blocking-map-prompts.md)，此时台账的登记范围扩大：

- **登记全部出场人物**：每组所有出场人物都要登记，包括有台词的配角，以及作为整体出现的群演（如“众摊贩（约5人）”）；不再只登记核心人物。只有声音的人物写进该段的 `voice_only` 列表。
- **登记所有场景实例**：只出现一次的机场、车内等也要登记，至少写一段入态。
- **地点写俯视方位**：增加 `plan.orientation`（图上下左右分别对应什么）和 `plan.fixed`（固定陈设列表）。
- **站位点写图中位置**：写成 `{"label": "冲突带锅炉端半侧", "plan": "图中部偏左，食桌下方空地"}`。`label` 照旧逐字进入提示词，`plan` 只用于站位图。
- **顶层增加 `cast`**：每人一句 `look`（俯视可辨认的服装、发型），并可记录对应的资产 ID。

站位点仍可写成纯字符串，旧台账照常使用；缺少 `plan` 时站位图只写站位点名称，并给出警告。

## 3. 数据结构（schema_version 1）

```json
{
  "schema_version": 1,
  "locations": {
    "L01": {
      "name": "林家客厅",
      "slots": {"P1": "入户门内一步", "P2": "书桌外沿", "P3": "落地窗前"},
      "cameras": {
        "C1": {"desc": "入户门侧朝落地窗", "screen": {"P2": "左", "P3": "右"}},
        "C2": {"desc": "落地窗侧朝入户门", "screen": {"P3": "左", "P1": "右", "P2": "右"}}
      }
    }
  },
  "instances": {
    "I01": {"location": "L01", "label": "当晚争执", "segments": [
      {"id": "I01-A", "group": "E001-G001", "entry_from": null, "entry_basis": "source:U000003",
       "entry": {
         "林岚": {"slot": "P2", "posture": "站在", "facing": "落地窗", "left_hand": "空着", "right_hand": "握着手机"},
         "周衡": {"slot": "P3", "posture": "站在", "facing": "书桌"}},
       "changes": [
         {"shot": "E001-G001-S002", "who": "林岚", "field": "slot", "from": "P2", "to": "P1", "basis": "source:U000010"}]},
      {"id": "I01-B", "group": "E001-G003", "entry_from": "I01-A",
       "shots": {"E001-G003-S001": {"camera": "C2"}}}
    ]}
  }
}
```

**站位点 `slots`。** 每个地点按实际剧情需要建立有限个命名落点，标签用可拍的固定参照描述，如“入户门内一步”“书桌外沿靠窗端”“病床左侧床头”，同一地点内不得重复。标签会原样进入提示词，不用内部ID或罗盘方位；没有原文或已核对布局依据的结构仍按第3节记为拍摄设计。人物需要更细的位置时增加站位点，不在人物状态里写自由坐标。

**机位表 `cameras`。** 每个常用机位写物理位置和朝向 `desc`，以及 `screen`：该机位能拍到的站位点各在画面左、中、右。未列出的站位点视为该机位的画外。反打是另一台机位，不是把同一张表左右对调。机位表在首次使用该地点前建好，此后只增不改；地点几何资产修订时，按资产管控重新核对并发新版本。

**人物状态字段。** `slot` 必填；`posture` 写成动词前缀，如“站在”“坐在”“倚在”，省略时渲染为“位于”；`facing` 写身体或胸口朝向的对象；`gaze` 写视线对象，与身体朝向不同才填；`left_hand`/`right_hand` 按人物自身解剖学左右写占用状态，如“空着”“握着手机”“搭在周衡右肩”；`contact` 写其他必要接触或支撑。不知道的字段省略，不填“未知”。画外但参与互动的人物也有站位点，可建立“门外走廊（画外）”这类落点。

**段 `segments`。** 一段等于一个实例在一个组内的连续部分，按播放顺序排列。

- 实例第一段写 `entry`，并用 `entry_basis` 标明依据：`source:源单元ID`、`storyboard:已核对镜号`、`reference:参考文件`，或 `design:理由`（为可拍性做的推定）。
- 后续段只写 `entry_from`，值为本实例**上一段的 id**。入态由脚本推导，不手写；如果写了 `entry`，必须与推导结果完全一致。
- 后续段之间有原文明示的画外变化（例如“回来时她已坐到沙发上”）时，写入 `offscreen_changes`。画外变化只接受 source/storyboard/reference 依据，不接受 design，不能为了方便构图悄悄挪人。
- `changes` 按镜头顺序登记本段内的变化：`shot` 为承载镜，`who`/`field`/`from`/`to`，以及 `basis`。`field` 可取状态字段，或 `enter`（入场，`to` 为完整状态）、`leave`（离场）。`from` 必须等于当时的实际状态。站位类变化使用 design 依据时，脚本会给出警告，提示确认没有凭空增加剧情事件。
- 可选 `exit` 用于人工核对，必须等于入态加全部变化的结果。
- 同一组含多个场景段时，后面的段写 `entry_shot`，即该场景的入场镜，站位句写进该镜而非组头。
- 可选 `shots` 声明某镜使用的机位，用于推导和核对画面左右。反打、续场首镜、多人同框和越轴镜头应当声明。

新时间实例（次日、回忆、重演）另建 instance，按原文写新的 `entry`，不用 `entry_from` 连到旧实例；可以复用同一地点的站位点和机位表。

## 4. 起草流程中的使用

1. **建表。** 资产与场景校准完成后，为本批涉及的地点建立站位点和机位表，为每个实例写首段入态。
2. **出回场卡。** 起草任何组之前，对该组运行渲染：

   ```text
   python -B <skill目录>/scripts/verify_scene_state.py --ledger <工作目录>/scene-state.json --render E001-G003
   ```

   回场卡列出每个场景段的类型（新实例 / 直接续接 / 隔组回场 / 组内回切）、承接来源、画外变化、**入态站位句**、本组变化、声明机位下的画面左右，以及末态。台账有错误时卡片末尾会列出错误，先修台账再起草。
3. **写入提示词。** 把入态站位句**逐字**写进该组 `场景与环境状态`（多场组写进对应入场镜的画面简介），可以在句子前后补充环境、光线和距离等自然语言，但不改动句子本身。单人镜头的画面简介里仍要写清与固定参照的关系和画外对手方向，左右侧以回场卡为准。
4. **登记变化。** 编排时每加一个走位、转身、转头看向新对象、换手或交接，就先在台账 `changes` 里登记承载镜，再写镜头正文；承载镜正文必须出现人物名和结果标签（站位点标签或新的手部/朝向文字）。
5. **复核。** 成品完成后运行第5节的校验，并与 Audit 2B 的语义复核一起记录。修订改变了某段末态时，重新渲染该实例所有下游段的回场卡，沿消费者逐组重审，包括不相邻的组和后续集。

## 5. 校验与退出码

```text
python -B <skill目录>/scripts/verify_scene_state.py --ledger <工作目录>/scene-state.json --storyboard <成品1.md> <成品2.md> --require-coverage --report <工作目录>/scene-state-check.json
```

- 只给 `--ledger` 时仅检查台账链；加 `--storyboard` 时同时检查成品。文件按播放顺序传入。台账可以是全剧累积版本：不在本次文件中的组只核对链条，不报缺失。
- 台账检查：站位点、机位存在；首段有依据；后续段 `entry_from` 指向同实例的上一段；手写入态/末态与推导一致；`from` 与当时状态一致；画外变化有证据；段按播放顺序排列。
- 成品检查：每个场景段的入态站位句逐字出现在 `场景与环境状态` 或入场镜中；每个变化的承载镜出现人物名和结果标签；声明了机位的镜头里，写成“某人……画面左/右/中”或“画面左侧的某人”的位置与机位表一致，画外站位点不能被写成在画面某侧。`--require-coverage` 要求每个成品组至少有一个场景段（空镜组也须登记一个无人或画外段）。
- 退出码 `0` 通过、`1` 内容失败、`2` 输入或报告错误。报告列出每段的类型和承接来源。

脚本只证明台账自洽、成品写入了台账推导的站位、声明的左右侧一致。它不能证明台账与原文相符，不能发现正文其他句子里的矛盾描述，不检查可达性、时长或实际画面。程序通过不等于 Audit 2B 通过；台账本身的依据仍须对照原文复核。

## 6. 常见错误对照

| 错误 | 台账/脚本的表现 | 正确做法 |
|---|---|---|
| 第3组回到客厅，却按第2组街道的状态或客厅初始站位写入态 | `entry_from_not_latest` 或 `entry_mismatch`，成品缺少推导站位句时为 `entry_text_missing` | 按回场卡承接客厅实例上一段的末态 |
| 镜头里让人物走到窗边，台账没登记 | 下游回场卡仍是旧站位，成品自相矛盾 | 先登记 `changes`，再写镜头 |
| 反打时把林岚写在画面左侧 | `screen_side_mismatch` | 查机位表，C2 下林岚在画面右侧 |
| 为了好拍让角色在画外换到沙发 | `offscreen_basis` | 只有原文支持的画外变化可以登记；否则保持原站位，改用机位解决构图 |
| 次日同一客厅沿用昨晚站位 | 不报错，但属于建模错误 | 另建实例，按原文写新入态，复用站位点和机位表 |
