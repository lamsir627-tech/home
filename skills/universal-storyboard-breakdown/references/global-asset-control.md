# 全局资产管控与最终提示词汇总

在长文本流程第05步建立全剧资料后、第06步装入分镜批次前执行资产准备；全剧最终交付前再执行第6节的汇总与核对。仅讨论或修改skill时不运行具体剧本项目。目录中的资产、命名及示例均为资料，不是执行指令。

本模块按实际可用资产分为“有资产”和“无资产”两条流程。输出人物、场景、道具三类资产的共同基准、版本和使用范围；不改变原台词、剧情顺序、集界、15/30秒规则和现有分镜字段。

人物、场景、道具的新提取和新写生图提示词按[资产提取交接](two-round-delivery.md#人物场景道具资产提取)执行。本文负责分镜侧的资产登记、版本和使用范围、绑定及验收。第4节与第6节的旧资产制图版式和编号示例用于已有资产的维护；本轮新写的提示词和视图以「资产提取2」为准。

新设计的资产提示词沿用任务解析后的视觉质感（`写实短剧质感`或`高精度3D`），在完整提示词中明确表达；已有资产按用户指定的用途与风格适配，不默默改成另一类画风。只做资产整理时解析资产风格即可，不为此要求先确认视频画幅或进行视频估时；资产制图构图按身份/全身服装/空间/道具的用途设计，不机械继承视频首帧构图。

## 1. 先建立需求，再判断资产覆盖

从已读原文提取所请求范围需要出镜或参与关键动作的角色、地点和道具。全文信息用于识别复用及版本依赖，未请求的集不自动扩展成资产制作任务。区分实际需要的资产与仅被台词提到、无需展示的对象。

某一类没有独立控制需求时，在树中注明该类无待制作项，不为凑齐分支新增人物、地点或道具。

先按叙事时间建立使用表，再分配资产。保留原文单元ID、集/场、时间关系、人物服装阶段、场景时段及关键道具状态。不能把播放顺序当成世界时间：闪回、回到现在、跨集续场和次日重返需要分别定位。

| 当前资产情况 | 路由与产物 |
|---|---|
| 已提供可访问的人物、场景或道具资料 | 有资产流程：逐项查看、对应剧情、核对版本，再给当前分镜绑定实际需要的资产 |
| 只提供了部分类型、部分人物或部分版本 | 仍走有资产流程；保留已有匹配项，缺口按无资产规则生成“待补资产”子树，不重做已确认资产 |
| 没有提供资产，也没有要求使用一套未交付的指定资产 | 无资产流程：先生成可直接使用的资产提示词总览树和版本使用表 |
| 用户要求严格使用某套资产，但文件缺失、打不开或无法识别 | 记录为“未收到/未检查”，不能冒充已绑定或擅自降级为无资产；先完成原文与需求整理，仅就影响当前工作的缺失资料询问 |

资产整理请求完成树/绑定表即可结束。新剧本分镜沿用本阶段的资产基准，按[两轮交付](two-round-delivery.md)完成首轮三份材料，已核对的图片计入清单，只等尚缺的参考。用户明确要求一次性交付时，可沿用已记录的文字设计，标明未绑定图片。资产提示词本身不触发生成、购买或上传。

## 2. 资产登记与责任边界

在剧本项目工作区保存 `asset-registry.json`（或等价结构化记录）及版本使用/批次绑定表；资产树、使用表和必要缺口说明作为独立用户交付物。不得把具体项目资产写进skill目录。

每个资产记录：

- 稳定ID、类别、名称及角色别名/地点/道具身份。示例ID：`CHAR-001`、`LOC-001`、`PROP-001`；ID只是项目索引，不是生成工具自动识别的引用语法。
- 基准版本和派生关系、原文来源、适用叙事时间和集场范围、固定特征、允许的变化。
- 实际参考文件/资源、文件修订摘要（工具可读时记录hash）、引用用途、查看依据和未见部分；无文件时路径为空，不编造路径或hash。
- 分别记录设计依据（原文明示/用户指定/参考可见/拍摄设计/未知）、资产状态（文字设计/待补版本/已检查参考/需解决冲突）及平台绑定状态（未绑定/已绑定）。有文件不等于检查过，也不等于已上传绑定。

按信息职责处理冲突，不使用一句“资产最高优先级”掩盖矛盾：

| 内容 | 决定依据 |
|---|---|
| 人物身份、年龄阶段、关系、剧情、锁定台词和必需动作 | 原剧本与用户明确改编要求；资产不能令儿童变成人或让角色提前知道真相 |
| 非剧情强制的固定外观、选定服装造型、场景固定结构、道具造型 | 用户指定并已检查的相应资产版本；删除与之重复冲突的旧描述 |
| 本镜站位、朝向、视线、持物手、开合、伤势和动作阶段 | 当前叙事时间及有效入组状态；定妆照的姿势、手中物或背景不自动继承 |
| 当前日夜、天气及实际光源状态 | 剧情时间与对应场景版本；日景布局参考不能被直接当成已具备夜景版本 |

资产与必需剧情条件确实不兼容时，明确冲突字段与影响镜头。例如只有封闭房间参考，而逃离情节必须有出口：可提议基于同母版补出口版本，不能一面锁定原布局一面在分镜里凭空增门。普通未明确的美术细节可记录为拍摄设计；改变关键身份、道具功能或空间条件需依据用户明确选择。只搁置受影响的绑定/镜头，继续其他独立工作。

## 3. 有资产流程：查看、适配、绑定

1. 查看实际图像/模型预览或用户明确提供的文字设定，按内容对应原文角色、地点、道具。文件名不能代替图像查看；看不到的背面、比例、门窗和服装细节保持未知。仅有一个视角时，可把必要的额外几何标为待补或拍摄推定，不能声称从图片看到了。
2. 明确每份资料用途：身份/定妆、服装、场景几何、道具、风格、构图，或特定镜头首帧。一张图可承担多个明确用途，但普通定妆图不锁定全剧姿态、背景、机位或光线；某镜首帧同时约束该镜的初始姿态、站位和构图，不当成所有镜头的共同首帧。
3. 对照剧情使用表选择版本。已有图像只覆盖它实际展示的衣装/场景状态；原文所需换装、日夜或破损版本缺失时，输出保持同一身份/几何/道具形制的派生提示词并标为待补，不能谎称变体图已制作完成。
4. 先校准场景母版，再排镜头。核对门窗、固定桌床的同墙/对墙、邻接、相隔与可通行关系，并清除旧文字中与实际参考相冲突的布局；不能把参考中门与床头的同墙关系写成位于相对两面墙，距离与通路仍须分别核对。采用已确认物理参照定义坐标，没有原文或已核对空间设计依据的罗盘方位不加入提示词；有依据的方位注明原文信息或拍摄设计，不把参考图画面左侧当成所有反打中的左侧，也不无依据镜像布局。看不到的结构按未知处理。人物站位与机位由当前动作推导，不复制场景参考里偶然站着的人。
5. 绑定当前组实际需要的角色服装、场景时段和道具版本。组内换场/换装按具体镜头分段绑定；不把全剧资产一起提交给每组，也不混用同一角色不同时期的互斥造型。
6. 改写现有七项连续性和组/镜头字段中的冲突描述。真实绑定时用对应资产引用加当前必要变化，避免反复改写已锁定的静态脸型、发型、材质和装修。引用文件名、ID或`@资产名`不代表已经传给生成器；只有目标工具实际支持且关联成功，才称平台已绑定。

没有可用的参考绑定通道时，可输出文字适配版并准确说明限制；把图片中已确认且当前镜必需的静态特征写入文字，不能仅给一个无法解析的资产ID并宣称角色已锁定。工具不支持的ID、路径、hash留在绑定表，不伪装成平台语法。

## 3A. 站位参考、首帧与实际画面承接

用于隔组同场景、直接续场及用户指定首帧/视频连续性的任务。人物身份图、无人场景图、剧情站位参考和镜头首帧分别记录用途：前两者不足以证明人物站位一致；站位参考描述一个有效状态，不把全场人物冻结在最初位置。状态来源与每组空间初态以[整本模式第3节](full-script-mode.md#3-全剧共用资料与连续场景状态)为准。

按实际请求阶段执行：

| 阶段 | 必需工作与可报告结果 |
|---|---|
| 只交文字分镜 | 把固定参照和当前人物初态写足，首镜与其一致，保存计划末态及接续来源；可完成文字分镜，不自动制作图片或视频。没有实际画面时，图像/成片检查记为未执行 |
| 已要求首帧提示词 | 从对应组首镜的初态与机位派生一段连续的静态画面提示词，含固定参照、人物关系、朝向与相关道具；不夹带走位过程或提前出现动作结果。每镜独立生成的平台按实际镜头起点派生，而非让整组共用首镜初态 |
| 已授权图片/视频制作 | 先核对实际模型的参考输入能力。支持参考图/首帧时，准备并检查对应状态与机位的图片，再按真实支持的用途绑定；仅支持文字时完整传入空间初态并标明参考绑定限制。参考未验收时保持待检查，不能称站位已锁定 |

同一场戏优先使用已核对站位参考，或该实例上一次出现的已验收有效末帧；不能取刚结束的另一场景末帧。前组末帧只有在当前镜头起点、机位和构图适用时才可直接作首帧。换景别/反打时，从有效状态派生并检查新机位的首帧；保持门窗家具与人物物理位置，按机位重新计算画面左右。遵守原跨组景别规则，不为复用末帧把两个镜头强行改成相同景别。图片未展示的画外人物继续由已核对状态约束，不把看不见当作移位证据。

多人抱扶/交接/控制、狭窄通路出入、同实例隔组回场及明显换机位时，重点准备能证明该段起态的站位图或对应机位首帧；按实际授权与模型能力选择。参考绑定记录角色身份、场景几何、剧情状态、首帧各自用途及作用镜段，必要时一图多用但逐项核对。多视图人物图不作为当前剧情的多个人或多个同时姿态。将图加入普通混合参考池不等于平台已将它设为严格首帧，必须核实真实模式和传参语义。

一组含多场戏时，组首帧只证明第一个入口，后场需要自己的入态与画面依据。若生成通道不能分段约束参考，先评估混合输入能否承担本段任务；复杂调度可在已授权制作中按模型实际能力拆为较短连续片段，保留原集/组/镜、音频顺序与时长映射，不借制作拆分改剧情或规避分镜契约。只有身份/空场景图时按事实标出站位图缺口；纯文字任务照常交付文字状态，不自动触发制图或付费生成。

生成后检查实际首帧、尾帧、切点两侧及涉及转身、走位、接触或出入画的关键帧：逐项比对固定参照布局、脚下/坐点、身体与头部方向、视线、拍摄侧、左右手占用、接触/支撑和动作阶段；相邻镜头与同实例隔组返回都要比较。使用实际视频时刻定位，不能把提示词计划秒数当成真实切点。只看首尾帧不能排除中途换位；需要判断动作过程、流畅度或音画同步时播放对应片段，静态采样只证明所见时刻。画面左右改变先结合机位和固定锚点判断，不能直接等同于人物反转。

逐段分别记录“文字状态、实际输入一致性、首帧、视频动作、跨段交接”的通过/失败/未执行/不可核对结果和证据位置。未入镜的既有状态可沿已核对动作链继承并注明推定；新的关键变化被遮挡且无其他已核对证据时保持不可核对，不借画外推定补出未完成动作，也不为普通近景机械补全景。纯文字或纯导入任务只完成已请求层级。已制作但下游依赖的关键状态失败/不可核对的画面不标为该接续的有效依据；修复后只重验受影响状态和消费者，任务成功码、引用存在或文本校验通过均不替代画面结果。

实际画面偏离计划时记录差异并修正/重生成受影响内容；失败或未检查的生成末帧不能自动升级为后续组的有效状态，也不能修改原文来迁就偏差。仅当该偏差不违背原文、且用户明确采纳为新调度时，才建立新状态版本并重审所有消费者。等待上游画面修复时，可继续不依赖该画面的文字或独立场景工作，相关成片交接保持未验收。

在项目本地保存：实例与组/镜、计划入/末态版本及来源、实际图片/视频位置与帧时刻、参考用途与真实绑定、检查结论/差异、下游使用范围。引用与核对记录不能代替正文里的空间描述。文字约束和参考绑定不构成视频一致性的保证；只能对实际检查过的范围报告画面核对结果。

## 3B. 实际生成输入版本

用于已授权媒体制作及生成异常追溯。每次投递在项目目录保存一条生成输入记录，例如 `generation-input-manifest.json`；这是本地工作协议，不是模型或平台字段。

- **期望与实际输入：** 保存已核对稿及状态版本、实际提交的完整提示词/规范化参数和摘要、有序参考身份/修订/用途/作用段、所选首帧、模型/模式、画幅、有效时长及目标项目/节点/行身份。只记录非敏感生产参数，不保存凭据或临时鉴权链接。平台同义参数冲突时先查明当前 schema 的有效值，不凭默认值猜测。
- **提交前核对：** 若执行消费远端节点，临提交前读回并比较当前完整提示词、参考顺序与有效参数；若接口直接消费请求体，比较将发送的载荷。节点名和人物引用相同不足以通过。发现与批准版本不一致时暂停受影响的投递，保存差异并查明来源；按实际修改授权协调，不静默覆盖并行编辑。
- **任务与输出：** 保存提交时间、返回任务ID、回执、输出资源与检查结果。平台提供实际任务输入或优化后提示词时一并核对，区别“本地期望”“已发送请求”“平台确认采用”；没有该证据就保留未知。记录原任务身份，交付未知时先查原任务而非盲目重发。
- **追溯边界：** 编辑器当前文字不证明旧视频当时使用的输入。任务上下文无法恢复时可分析当前文字和实际画面，但明确原输入未证实，不把差异直接归因于某一版提示词。图片数量、文字长度或某种参考姿态只可作为待验证风险，不能单凭相关性报告根因或承诺修订必然成功。

复用本轮已核对记录，只有新提交、相关输入变化或未决差异才重做对应核验；纯文字/导入任务不为填记录而调用生成接口。

## 4. 无资产流程：完整提示词总览树

以下为沿用旧资产制作规范时的历史示例。新资产按[资产提取交接](two-round-delivery.md#人物场景道具资产提取)制作。

先输出三类总览树，叶节点连接对应的完整资产提示词卡和使用范围。不能只列“男主/医院/手机”清单，也不能用“其余同理”代替需要制作的版本。长文本可分文件按树节点链接，最终核对所有必需叶节点有卡、有来源、有用途。

完整的静态外观、服装、场景和道具设定集中在资产设计卡；视频组按实际绑定能力重复必要不变量：已绑定时简写，文字适配时写足。视频提示词的清洁规则不禁止资产设计阶段说明静态特征。原文没有指定的颜色、面貌等可作一致的美术设计并标明依据，不能伪称来自原文或用户素材。

### 4.1 人物：固定身份 → 服装 → 必要状态

- 每个角色建立稳定身份母版：原文年龄阶段、可见轮廓、脸型、发型/发色和体态等必要辨识点。跨年龄阶段另列关联版本；不把“六年前”机械生成为另一个长相。
- 根据剧情实际生活时间、场合、身份行动和明确换装建立衣装版本。上班、睡眠、住院、婚礼或明确换衣可触发所需衣装；不能每集、每场、每次转场自动换衣。日期变化只触发检查，不等于必须新衣。
- 同一次连续事件跨组跨集保持同一衣装。换装生效范围写到原文事件/场景；未写换衣过程但新场合必需的服装可作为明确标记的美术设计，不补拍换衣剧情。
- 泥污、湿透、血迹、破损、伤口/包扎、摘下外套、领带用途改变、编辫等按事件形成状态层。通常记录状态差量即可；只有稳定复用或辨识/接触动作确有需要时才单独制图。不能因换场、夜转日或重新载入定妆图而恢复洁净、痊愈或长出已摘下的饰物。
- 后续时间的服装和伤势不能污染较早闪回；闪回结束后恢复现在时间线的有效状态。

人物卡包含：资产/版本ID、父身份与服装版本、源依据及用途、适用集场/叙事时间、固定项、变化项、完整生成提示词、需要的参考视角。默认以单角色中性姿态、全身服装可见、纯白背景制作身份/定妆资产；确有辨识需要再补正面脸或背面衣装视图，避免全员机械生成同样数量的视角。白底要求仅用于新人物资产设计，不要求重做用户已提供的背景图，也不进入剧情镜头。

### 4.2 场景：固定地点母版 → 所需时段 → 必要环境状态

- 同一地点先锁定门窗、层高、固定家具、通路、材质与相对尺度，给出可复用的空间母版。必要时增加布局示意/补视角提示词；不从一个透视图臆断不可见结构。
- 先列实际时间使用表，再制作所需时段：清晨、白天、黄昏、夜晚等只是可选标签，原文只出现日/夜就制作日/夜，不替所有场景强制生成四时段。
- 每个时段版本继承同一几何，明确窗外亮度、主光来自哪个固定窗/灯、灯具开关、冷暖关系和必要天气。夜版改变照明与可见环境，不重新装修、挪门、换床或镜像。
- 同地点次日重返另建`scene_instance_id`；如果布局、时段、天气、灯光和环境状态相同，可复用相同场景资产版本。不要按每个日期复制一张相同图，也不要用复用资产继承前一天的人物站位。
- 原文明确雨天、停电、火灾、破坏等，再按事件建立环境状态。固定几何的真实改变另建结构修订；火后残损持续到有修复依据时。只生成实际使用组合，不作“所有地点×所有时段×所有天气×所有破损”的笛卡尔积。
- 跨日/闪回和日夜转换按叙事时间选版本；原文未明确时段时记录未知，能不影响剧情地设计则说明假定，不能编造具体日期或日落时刻。场头与正文冲突先列依据，关键冲突不靠资产图悄悄改剧情。

场景卡包含：地点/几何/时段版本ID、母版与固定锚点、时间及天气依据、适用实例、光源与状态差量、完整生成提示词、必要补图。场景母版以可读空间结构为主体，人物站位留给分镜；材料和家具不随不同机位变成新地点。

### 4.3 道具：物件身份 → 必要形态/功能状态

- 优先控制推动剧情、反复出现、被触碰或提供证据的道具，不把每件普通背景杂物都升级为独立资产。必要背景物可纳入场景卡。
- 锁定尺寸级别、轮廓、材料、颜色、结构和识别细节；开/合、激活/熄灭、完整/破损等仅按实际使用建立版本。
- 同一物件换手、移位不新建物件身份；持有人、持物手和位置进入镜头状态。剧情明确的真品/替身、两只相似物件、不同内容载体分别登记，不能靠“同一个道具不同状态”把它们合并。
- 所需刻字、屏幕或证据文字只使用核准原文，缺失内容不编造；必要文字素材与生成画面分开安排。图片中偶然出现的手机或饰品不自动成为每个镜头的持物。

道具卡包含：身份/状态版本ID、源依据及使用范围、形制固定项、功能与状态差量、完整生成提示词、必要操作视图；握持动作和当前归属另入状态表。

### 4.4 树与使用表的组织示例

以下名称和ID仅为格式示意，不替代对实际剧本的提取；“待制图/文字设计”不表示图片已经生成。

```text
全局资产总览树（覆盖：所请求原集范围；版本：本次资产修订）
├─人物
│ └─CHAR-001 林安｜身份母版
│   ├─W01 工作服｜同一晚事件跨第1—2集
│   │ ├─S01 洁净｜进入雨中之前
│   │ └─S02 湿衣/袖口泥痕｜雨中摔倒之后，状态提示词；按复用需要制图
│   └─W02 病服｜次日住院后；保留仍存在的伤势
├─场景
│ └─LOC-001 诊所走廊｜几何母版G01
│   ├─G01-DAY｜白天窗光/所需灯具状态
│   └─G01-NIGHT｜同门窗与固定家具/夜间灯光
└─道具
  └─PROP-001 怀表｜同一物件
    ├─CLOSED｜闭合外观
    └─OPEN｜表盖打开、原文规定的内侧细节
```

每个需控制叶节点的卡必须写足可独立使用的正向生成文字。派生卡明确继承的母版/文件和变化；当下游无法实际绑定母版时，展开必要不变量，不能只写“同母版，改成夜晚”。树内链接指向实际卡，不用不存在的图片文件链接充数。

版本使用表至少列：`原集/场与来源 → 叙事时间/连续实例 → 角色身份+衣装+状态 → 地点几何+时段+环境状态 → 道具身份+状态 → 依据/待决项`。组号尚未生成时按源事件定位，分镜完成后回填实际集/组/镜；不得为建资产表预先捏造组号。

## 5. 合流到分镜与检查点

有资产路由交付当前绑定表及必要的待补子树；无资产路由交付完整树、提示词卡和使用表。两路共同保存资产修订，并为每个批次仅加载当前需要的条目，不在每组重复整本树。

批次包新增当前资产修订、实际参考及用途、角色衣装/状态、地点时段版本、道具版本、绑定可用性与未决冲突。各组继续使用原有七项全局连续性和字段：

- 全局`主要人物`写相关身份与当前衣装版本；每组`主要主体`按[最终交付简表](final-delivery-format.md#主要主体人物场景道具简表)写“人物名（简单服饰描述），场景名（状态），道具名（状态）”。完整静态设定由资产卡/独立汇总及实际投递的参考资料承载，未绑定图片也不将长外貌段回填到该简表；可用参考和平台绑定仍需按事实记录。
- `空间母版/场景与环境状态`落到选定地点几何和当前时段，并写入该镜真实初态。
- `关键道具连续性/画面简介`写实际持有人、手、位置和当前形态，不能用道具资产替代动作记录。
- `光线与色彩基调/设计`服从当前资产时段和物理光源；优化风格不能把夜景改成白天或另加窗灯。

资产制作的白底、标准站姿、视图排版等不复制进剧情分镜。资产参考角度也不限制所有镜头使用同一侧脸；依现有说话者面部、正反打、轴线及可见人数规则组织摄影。

逐批复核：需求叶节点是否覆盖；引用是否真的可用；角色、衣装、场景时段与道具是否选对；静态描述是否冲突；变化是否由事件触发；日夜是否同几何；多场组是否分别绑定；每组是否可独立理解。把文字资产设计完成、图片可用和实际视频验证分开报告，不能把树完成写成资产图片验收通过。

检查点保存资产修订、每批依赖条目/版本、平台引用对应和当前状态。收到新资产、改衣装、改场景几何或换参考版本时，先定位影响范围再重审相关镜头及其下游连续状态；不覆盖既有已交付文件，除非用户要求更新它们。几何变化需重算站位与机位，纯外观变化仍需核对服装/道具差量；台词和原文版本不会因换资产而自动改写。

## 6. 全剧最终交付：人物场景道具提示词汇总

最终交付全剧分镜/视频提示词时，必须同时交付一份独立的《人物场景道具提示词汇总》。前期已给过资产树、分散提示词卡、版本使用表或已有图片绑定表，均不能替代这份最终汇总；有资产、无资产和混合路由都适用。仅讨论/修改skill不生成具体剧本汇总，仅请求资产或单组工作也不因此扩展到全剧。

- **内容范围：**以最终已核对分镜、当前资产修订及使用表为准，汇总全剧实际需要的人物、场景和独立控制的道具。包括必要的身份/年龄、衣装/持续状态、地点几何/时段/环境状态、道具形态版本；同一资产同一版本合并一次并汇总使用范围，不能混并互斥版本。排除已弃用版本、仅对白提及且不需展示的对象及无独立控制需要的背景杂物；背景物仍保留在对应场景提示词中，不作无依据的版本组合。
- **文档组织：**首页说明剧名、实际覆盖集数、对应分镜/资产修订与视觉质感。正文固定分为“人物提示词”“场景提示词”“道具提示词”三部分。每项包含编号/名称、版本、适用集/组（必要时到镜）、简要用途与设定依据、完整提示词正文、实际参考与可用状态。某类无独立资产需求时明确写“无独立需求”，不为凑齐类别新增资产。
- **可直接使用：**每个所需版本的完整提示词正文放在汇总本身，可单独复制使用；不能只交名称树、索引、卡片链接、内部ID、“同上/同母版”或变化差量。展开该版本必需的身份、服装、几何、光源或形制不变量并合并当前状态，与最终分镜一致。附加卡片链接可用于追溯，不能替代正文。资产提示词沿用本任务已确认质感；资产版本、视图和制图版式按「资产提取2」及本轮约定处理，不机械套用视频镜头的构图。
- **已有参考同样汇总：**优先沿用与最终资产匹配且已核对的现成提示词；只有参考图而没有原始提示词时，依据实际已查看的特征整理“参考复现/适配提示词”，不声称找回了图片的原始生成词。保持已确认身份、造型、几何和材质，不为汇总重做资产；未见细节不伪称可见，必要设计按既有规则标明依据。文字设计、参考图片可用、平台已绑定分别如实记录。
- **最终核对：**从最终分镜逐项回查所需资产及版本，确认每项都能在汇总找到完整正文；再从汇总回查实际使用范围，清除废弃或冲突条目。重点核对角色别名/年龄、衣装伤势、场景几何和日夜、道具身份形态、视觉质感及参考状态。资产相关分镜修订后同步更新本汇总；前期草案不能冒充最终版本。存在缺口或未知依据时准确标记范围，不能宣称汇总完整。
- **同批交付：**默认在本剧输出目录保存 `人物场景道具提示词汇总.md`，可沿用项目编号或用户指定格式；一份文档集中包含上述正文。最终回复同时给出全剧提示词和本汇总的可用链接；若有交付索引或压缩包，也必须纳入本汇总。无文件工具时，作为同次交付中独立且清晰分隔的完整文档正文提供。中途/指定范围的汇总准确标注实际范围；范围未齐或汇总未交付，不能报告全剧最终交付完成。汇总不插入各集七项全局连续性或每组视频提示词字段。

用户要求同步飞书多维表格，或当前项目已有适用的授权绑定时，按[飞书 Base 资产交付](lark-base-asset-delivery.md)把本次已核对范围的资产版本同步到真实目标表。保持人物、场景、道具分类及一版本一记录，包含完整正文、实际使用范围、来源和状态；沿用本地稳定 ID，不为同步改写剧情或重建资产。本地汇总继续作为必交文件，飞书写入与读回结果另存项目工作记录。
