# 长文本默认工作流程

所有剧本转换默认执行本流程，不以字数决定单集或多集。短文本可以缩小记录与批次数，不能跳过原文核对。仅索引、预处理或讨论 skill 的请求按其范围结束，不自动生成分镜。

本文件负责依赖顺序与可执行校验接口；步骤是检查关口而非每次都需展示的流水账，已满足且版本未变的前置结果直接复用。`full-script-mode.md` 负责多集范围、原集边界以及可共用的场景状态与续作规则；主文件的作业主流程及镜头契约是第07步的编排依据。台词、机位与风格要求仍按对应参考执行。

## 01 输入全文并保存原文版本

保留用户提供的原文件。将待处理正文保存为 UTF-8 文本快照，以文件路径、字节 SHA-256、原文字符位置标识修订。Word/PDF 等输入先用适用的文档工具提取正文并核对页段、表格和文字顺序；以下脚本只接收 `.txt/.md`，不把二进制文档直接当文本读取，也不能证明文档提取无误。

在当前剧本任务的工作目录建立记录，在其输出目录保存成品。不要把剧本数据、依赖包或进度保存进通用 skill 安装目录。已有原文修订与成品保留，新修订建立新工作记录。

## 02 分块读取并建立原文台账

使用 [build_source_ledger.py](../scripts/build_source_ledger.py) 构建原始台账：

```text
python <skill目录>/scripts/build_source_ledger.py --source <原文.txt> --out-dir <新的工作目录>
```

脚本保存 `source.snapshot.txt` 与 `source-ledger.json`，对每个出现位置分配全局唯一 `U000001` 等ID，保留原集号、行段位置、原文、初步类型和台词切片。重复台词不去重，空行和未知内容不丢弃。首次构建拒绝覆盖已有快照或台账。

按原场景与自然段读取快照；单场过长可分窗口读取，用字符范围/源单元ID记录已读部分。工具结果截断不算已读，摘要不能替代未读取的原文。机器已索引完整文件，也不等于模型已经阅读全部正文。

自动识别仅为候选。逐块核对集界、角色、动作、VO、旁白、字幕和双语配对；未知或有歧义的行保持待判定。不要一次把所有 `reviewed` 改成 true，也不要把无法识别的有声内容改成非有声来消除错误。

## 03 核对台账与原文

先运行结构检查，确认快照修订一致、字符覆盖无缺口或重叠、每条 raw 等于实际原文切片：

```text
python <skill目录>/scripts/verify_storyboard.py --ledger <工作目录>/source-ledger.json --structure-only --report <工作目录>/source-integrity.json
```

完成逐块内容复核后，将相应单元标为 `reviewed: true`。可修正分类、集场、角色、发声状态和台词切片，但保留原文不变；必须拆分或合并原单元时保留追溯关系、连续字符覆盖并重跑检查，更新已有映射。双语中的中文译文设为 `translation`，与英文单元使用相同 `pair_id`，不发声；字幕设为 `subtitle`，也不进入成品音频字段。

随后运行：

```text
python <skill目录>/scripts/verify_storyboard.py --ledger <工作目录>/source-ledger.json --ledger-only --report <工作目录>/source-review.json
```

进入详细分镜前，全部已提供原文应读完并完成索引核对，明确未知项及实际范围。`--structure-only` 通过仅代表字符完整；`--ledger-only` 还要求分类已复核，但不能证明分类理解正确。真正影响台词/角色/集界的未决问题应先解决；不影响当前批次的其他问题单独记录，不伪造“全部通过”。

## 04 确定处理范围

分别记录收到的原文范围与用户请求的交付范围。完整单集仍是单集，多集才进入整本分支；保留原集号，不能按每几千字造一集。只请求部分集/组时，全文用于理解，成品仅覆盖所请求范围。源集界不明且用户要求新分集时，才针对集界询问。

新任务在估时/起草前按主规则确认画幅、解析时长模式和风格，并保存到任务清单。同一任务续作读取已核对参数，不因“继续”二字重置画幅、15/30秒模式或3D风格；用户更改参数时记录影响范围和新版本。

## 05 建立全剧资料

建立角色ID与别名、地点固定结构、叙事时间线、道具身份、服装/伤势阶段、各角色在各事件之后已知的信息。全剧未来信息只供规划，不提前变成当前角色的认知或表演依据。有隐瞒、误解、反转或跨时间线时，按 [叙事证据与依赖](narrative-evidence-and-state.md) 分开记录事实、角色认知与观众揭示时间，并用源单元连接必需动作与后续使用。

所有模式共用 [full-script-mode.md](full-script-mode.md) 第3节的 `location_id`、`scene_instance_id`、场内状态与跨场持续事实机制；单集多场景同样适用。每条关键事实记录来源单元ID，区分原文明示、已核对分镜、参考画面可见证据、拍摄推定和未知。未知去向不能被补写成新事件。

### 05A 全局资产管控：有资产 / 无资产

在进入本批分镜之前，执行 [global-asset-control.md](global-asset-control.md)。从全剧资料与叙事时间提取所请求范围的人物、场景、道具需求，登记已有资产及版本覆盖。

`有资产：实际查看 → 角色/地点/道具对应 → 按剧情适配服装、时段与状态 → 当前批次绑定`

`无资产：需求与时间表 → 人物/场景/道具提示词总览树 → 完整提示词卡和版本使用表 → 文字资产基准`

部分资产按条目合流：沿用已检查的匹配项，只对缺失资产或版本生成待补子树。已指定但未提供/不可读的资产保持未解决，不假装已经匹配。人物身份与服装/脏损分层，场景固定几何与日夜/天气分层；只规划原文实际需要的版本。

先保存资产阶段产物。仅请求资产整理时交付后结束。新剧本分镜默认进入第06步编排并锁定内部结构，按[两轮交付](two-round-delivery.md)交三份首轮材料，核对已给图片并等待仍缺的参考，再进入第二轮。用户明确选择一次性交付时，可在第06步后沿用文字资产直接完成分镜，并如实记录图片绑定状态。

## 06 加载本批资料包

每批记录明确的源单元范围，按可用上下文、实际输出容量和状态依赖选择能完成核对的自然场景/完整组。短单集可一次完成；复杂段落在可靠交接处缩小批次，不强制每批只做少量组，也不按模型标称上下文额度硬塞整剧。窗口不按固定字数硬切台词、接触动作或原集边界。若一个有声原文单元需跨组，可在同一批中完成其所有片段后统一校验；批次交付不能把半条原文冒充已完成覆盖。

本批输入至少包括：

- 本批精确原文及单元ID，必要的前后原文上下文；正文始终从快照读取。
- 相关角色与场景资料、当前叙事时间、角色此时已知的信息。
- 当前资产修订、实际参考及用途、角色衣装/状态、场景几何/时段、道具身份/形态、绑定可用性与待补项；组内多场分别对应。
- 正确连续场景实例的有效入组状态、跨场持续事实、必要的前两镜信息。
- 原文覆盖范围、交付范围、已锁定参数、上游状态版本与待处理问题。

剧情摘要仅用于定位和节奏，不能作为锁定台词、确定持物状态或新增因果的唯一依据。把本批必要的真实初态写入实际提示词，使分组可独立使用。

## 07 生成本批分镜

调用主文件的作业主流程及 [镜头契约](storyboard-contract.md)：保留原文，先按[动作与对话时序匹配](source-text-and-shot-rules.md#3c-剧本动作与人物对话时序匹配)读取对话前后画面、判定先做再说/边做边说/说完再做及混合阶段，再按主声轨和动作时间线估时，设计镜头、表演与光色。时序依据和对应集组镜纳入已有动作记录。先按已建立物理参照排机位；焦点、景别和画幅变化不能重建人物站位。

生成 Markdown 成品及独立的 `storyboard-map.json`。源ID和机器字段只进工作记录，不插入视频提示词。正文遵循原有集标题、七项全局连续性、组标题与镜头格式。

选定资产版本写入现有主体、场景、道具和光线描述；实际支持的参考别名可以使用，内部ID与hash不能冒充可用引用。无图或无法有效绑定时提供足够的固定文字描述；仅在当前版本已检查且有效绑定时省略重复静态特征，但必须表达当前动作和状态变化。

每个镜头恰有一个 `字幕/角色台词/旁白` 字段；无声写 `无`。所有有声行都写成 `说话者标记：原文片段`，单条也不能省略角色、VO或旁白标记，并与台账的 speaker 一致。同镜多段按播放顺序每行一段，不把多个说话者挤在同一行。中英配对沿用 `英文主声轨（锁定）— ROLE: Exact source fragment`。由脚本反读这些实际字段，不检查另一份手工抄写的“成品台词表”。



### 音频字段的源空白与排版

说话者冒号后允许零或一个 ASCII 空格作为字段排版；此后所有字符属于锁定源片段，包括真实的前导/尾部空格。源片段以空格开头时，先写一个排版空格，再原样写片段。英文按词边界拆镜时，把分词空格计入相邻片段的源切片并原样写入对应音频行，不丢弃它，也不在片段内部改空格。

音频行尾只保留真实原文空白，不额外添加 Markdown 双空格换行；保存/汇编成品时不要对音频内容使用 `strip()` 或自动清理尾空白。程序仍对全部源字符与映射逐一核对，不进行空白归一化。若传输或编辑器已清理空白，回到快照与片段映射恢复成品文件并重新核对，不伪报通过。

## 08 程序核对成品台词

运行 [verify_storyboard.py](../scripts/verify_storyboard.py)：

```text
python <skill目录>/scripts/verify_storyboard.py --ledger <工作目录>/source-ledger.json --storyboard <成品1.md> <成品2.md> --mapping <工作目录>/storyboard-map.json --report <工作目录>/dialogue-check.json
```

- 默认核对全部原文；只交付指定集时增加 `--episodes 1 3` 等原集号。
- 批次校验可增加 `--start-unit U000020 --end-unit U000048`，端点必须覆盖本批全部源单元。命令的成品文件和映射仅含本次核对范围；完整集汇总时另以完整范围重跑。
- 文件按实际播放顺序传入；单个检查文件须带正确集标题和组号。分批文件可重复集标题以便定位，汇编最终成品时保留一次，并重新校验实际汇编文件。
- 交付范围与核对范围分别记录。仅交付指定组但其台词跨组时，本脚本仍按完整源单元核对：可纳入同一原文版本的既有相邻成品及映射，扩大到覆盖完整单元的连续范围，实际只交付请求组。缺少这些成品时，记录已核实的片段和未能核对的完整单元，不删除源片段或宣称程序全覆盖通过；新生成任务在第06步将完整单元安排进同一核对批次。
- 字符切片必须连续覆盖每个选定有声单元，保持原文、说话者、原集号与播放顺序；成品多出的未映射台词也判失败。原文重复出现分别覆盖，不能用一个成品片段抵两次。
- 返回码 `0` 为该检查范围通过，`1` 为核对失败，`2` 为输入/执行问题。失败先修复并重跑，不改原文、缩小交付范围或伪造映射来取得通过。

报告包含实际范围、原文/台账/映射/成品摘要和错误定位。程序检查字符、分类复核标记、源片段覆盖、角色/集数/顺序、标准音频字段及组内秒数加总；它不判断原文分类是否理解正确，也不验证动作语义、空间几何、人物知情或最终生成视频。

## 09 复核剧情与连续性

单独记录内容复核结果。逐项检查必需动作是否真的出现在画面，是否凭空新增事件、关系或道具，角色是否提前知情，人物位置/朝向/视线/持物是否有依据，情绪是否承接正确。对照动作与对话的时序记录反读实际画面/声音字段，检查前置动作、并发区间、后置动作与关键词触发点；这项语义核对不由程序的台词覆盖或秒数加总代替。

每个原文必需动作要能定位到具体集/组/镜和对应描述；用一句“动作都已覆盖”不能代替映射。按[镜头复核 Audit 2B](review-mechanisms.md#audit-2b-scene-state-handoffs-including-nonadjacent-returns)逐条对照实例接续链与实际组/镜正文：同一场戏隔组返回承接最近有效末态，新时间实例才按原文重建站位；跨场持续事实按有效证据继承。记录接续来源、差异及其依据，不能用相邻组检查代替隔组回场检查。缺乏上集镜头时区分暂定计划初态与已核对实际末态；实际媒体按全局资产管控第3A节另行验收。

按资产使用表核对当前衣装、伤势、场景时段/灯光、门窗家具、道具形态及持物，检查参考用途是否正确；不能把夜转日、切镜或换集当成自动换装/痊愈/修复。程序台词通过不证明资产匹配，需独立记录资产适配复核。

修复时按 [叙事证据与依赖](narrative-evidence-and-state.md) 只改受影响的镜头与依赖状态，记录持续事实的传播范围及停止依据。任何台词字段或镜头顺序变化，都重跑第08步；状态变化沿同一实例及跨场事实依赖复核。所有主 skill 的逐镜、构图、光色审核也应完成。

## 10 保存成品、状态与检查点

只有本批文字程序核对及内容复核均完成，才标为 `已核对`。使用 `未处理 / 已起草 / 已核对 / 需重审` 状态；后续修改令对应检查结果失效，不能复用旧摘要冒充新版本通过。

保存本批成品路径与摘要、校验报告、源范围、入组/末态与依赖版本、参数、下一源单元、当前集组号/目标时间、前两镜摘要。机器报告和语义复核状态分开保存。若仍有具体问题，记录范围与原因；其他独立工作可继续，但该批保持未完成。

同时保存资产修订、本批资产条目/变体依赖及实际引用对应。后补参考或替换版本时，定位并重审相关外观、几何、衣装/道具状态和下游承接；不把旧资产版本的审核结果用于新成品。

按同样的第06—10步处理后续批次，不因批次结束增加审批停点。中断后读取检查点与原文版本，从下一未核对单元继续；上游修订则沿依赖重审。同一单集跨批不重编号，多集按原集界重新从第1组与00:00开始。

## 11 核对全部请求范围

用实际最终成品与合并映射重跑覆盖核对，确认批次拼接没有新增重复或漏段；检查每个请求集、源单元、必需动作、跨组/跨集状态和所有待重审项。指定范围通过不得写成整本通过；`--structure-only` 或单批报告也不得代替最终汇总结果。

核对所有需求资产叶节点均有实际匹配或明确文字设计/待补状态，所有已生成镜头使用有效版本；明确选择一次性交付或同意文字补缺时，可按文字完成相关分镜，并如实记录绑定状态。尚未解决的关键资产/剧情冲突准确列明。

全剧最终交付前，按[全局资产管控第6节](global-asset-control.md#6-全剧最终交付人物场景道具提示词汇总)从最终分镜与有效版本汇编一份人物场景道具提示词汇总，双向核对资产/版本覆盖、完整正文和使用范围。已有素材路由也必须提供；分镜或资产修订后重审受影响条目，不能直接交付前期草案。

所有模式采用已有集末短尾组规则：不足目标组长时保留真实时长，逐镜限制仍适用，不跨原集借句或编造动作补时。只生成指定组且该组不是集末时不能套用尾组例外。范围不全或历史边界不可核对时，准确声明完成与未核对范围。

## 12 交付

交付实际分镜、已完成范围与简短检查结果。工作台账与程序报告另存，不混进视频提示词。工具确实不可用时，可给出草稿和实际人工/模型复核范围，明确程序检查未执行；不要声称具备自动验证或长期记忆。

资产阶段的总览树、完整提示词卡、版本使用表或已有资产绑定表单独交付，说明文字设计和图片可用范围；只请求该阶段时不要求制作分镜、运行不存在成品的台词核对或生成图片。

最终交付全剧提示词时，同批提供已核对的《人物场景道具提示词汇总》独立文档及链接；若有交付索引/压缩包，同步纳入。完整要求见全局资产管控第6节，前期卡片或仅名称清单不替代此最终交付物。未完成全剧时如实标明已有汇总范围，不冒称最终完整汇总。

## 脚本数据约定

`source-ledger.json` 使用 `schema_version: 1`：

- `source`：`path`（快照路径）、`sha256`（快照原始字节）、`char_count`（UTF-8 BOM解码后Unicode字符数）。CRLF不转换；字符位置不等于字节或UTF-16位置。
- `units`：按原文顺序，`id/order/start/end/raw/episode/scene/kind/speaker/spoken_text/spoken_start/spoken_end/audible/reviewed/pair_id`。所有源单元无缝覆盖全文，切片区间左闭右开。
- `kind`：`dialogue/vo/narration` 为有声；`action/heading/metadata/subtitle/translation/blank` 为非有声；`unclassified` 不得视为已核对。非有声的 spoken 三字段均为 null。
- `episode`：原集号的数字字符串；没有集标题的单集使用 `1` 作为暂定工作标识，不推断新集界。多集标题前的非集说明可以为 null，归属需复核。
- `speaker`：核对过的原说话者或VO/旁白标记，与成品标记一致。角色别名可用于内部关联，不能借此篡改原角色归属。
- `translation` 必须有 `pair_id`，指向同集的一条已核对有声单元；双语配对的理解由内容复核负责。

`storyboard-map.json` 使用以下结构，数值为示意，必须按当前原文实际计算：

```json
{
  "schema_version": 1,
  "source_sha256": "快照实际SHA-256",
  "fragments": [
    {"unit_id": "U000020", "start": 310, "end": 326,
     "shot_id": "E003-G002-S001", "audio_index": 1}
  ]
}
```

`start/end` 是原文绝对Unicode切片位置，必须位于对应有声单元的 spoken 范围。`shot_id` 为原集号、组号、组内镜号各至少三位的复合ID；`audio_index` 是该镜音频字段中第几行有声内容，从1开始。每条成品音频行只对应一个原文片段；一个源单元可跨镜拆成多个顺序片段。脚本从实际成品读取文字，不接受映射中的备用台词来代替核对。

原文动作的集组镜映射、时间线事实、内容审核和检查点可使用独立记录，与本脚本JSON并存。旧台账若格式不同，先转换到本约定并核对原文；旧的文字“通过”说明不能代替新报告。
