# 整本剧本模式

本参考是默认 [长文本工作流程](long-text-workflow.md) 的多集分支，负责原集范围、逐集调度、跨集状态和续作。第3节的物理状态与持续事实、第5节的保存原则同时供单集长文本复用。原文快照、脚本台账格式、程序核对和线性执行顺序以长文本参考为准。逐镜编排沿用主 skill；本模式不自动替换现有主体轮换、景别比例或表演规则。

## 1. 范围与入口

同时记录 `source_scope`（实际收到的原文范围）与 `delivery_scope`（用户要求生成的范围）。

| 输入与要求 | 处理方式 |
|---|---|
| 一集完整文本，包含多个场景，用户称其为“全文” | 默认长文本流程的单集范围，保留台账、程序检查与状态；不因篇幅或场景数拆成多集 |
| 多集原文，要求整本/全剧分镜 | 全文预处理，按原文集序生成全部已提供集 |
| 多集原文，只要求第N集、某几集或指定组 | 全文用于理解与连续性；只交付指定范围 |
| 明确要求整本模式，但原文没有可辨认的集界 | 先建立原文与场景索引；若需多集输出，询问集界或是否允许新分集，不自行按字数造集 |
| 只要求预处理、索引或场景资产整理 | 完成所要求阶段，不自动扩展到最终分镜 |
| “继续”同一整本任务 | 读取已核对的任务记录，续作下一未完成单元 |

保留原文集号、集序、标题与缺号，不把收到的第3集改名第1集。别把剧中台词里的“第几集”或场景编号识别成集标题。记录实际收到的集范围；用户称“整本”但提供内容不全时，不声称已读取缺失部分，不补写缺失集。

新任务先解决主 skill 的画幅、时长模式与风格，再估时、分组或起草镜头。同一任务的续作读取已经明确的参数；不得因为用户只说“继续”而再次询问画幅或重置风格。用户改变参数时，记录新版本和影响范围，不把不同参数的成品混作一个未标记版本。

## 2. 全文索引与原文台账

在任何单集的详细分镜之前，读取全部已提供原文，建立可追溯记录。长文件可分块读取，但保留完整原文与精确来源；剧情摘要不能替代原文读取或作为锁定台词来源。文件不可完整读取时说明实际范围，先处理可独立完成的部分，不虚报全文分析完成。

工作记录至少包含以下信息，允许用 JSON、JSONL 或等价结构化表存储：

| 记录 | 必需内容 |
|---|---|
| 任务清单 | 任务ID、原文文件/文本快照及修订标识、已读范围、原集号与顺序、交付范围、画幅/风格/时长/语言政策、输出位置 |
| 原文单元 | 唯一ID、原集号、场景段、顺序、原文位置、类型、原文全文、原角色标记、是否属于主声轨、双语配对ID（适用时） |
| 分镜映射 | 原文单元ID及片段起止、集/组/镜ID、实际交付文本、动作对应画面、状态（未处理/草稿/已核对） |
| 场景与状态 | 地点ID、连续场景实例ID、物理参照、人物与道具状态版本、跨场持续事实、来源与交接关系 |
| 续作记录 | 已核对成品、当前集/组、下一原文单元及片段位置、待修问题、前两镜摘要、各连续场景最近有效状态 |

原文单元包括对白、VO、旁白、动作、场头、字幕参考与必要说明；不只提取有声台词。原文位置优先使用原文件页段/行号，并保留能复核的精确文本；需要按字符切片时，明确为零起点、左闭右开的 Unicode 字符位置。

使用复合集组镜标识，例如 `E003-G002-S004`；原文构建脚本使用独立全局源ID，例如 `U000007`，原集号另存 `episode`，不要因重新拆镜而改变源单元ID。遵守长文本参考的 `source-ledger.json` 与 `storyboard-map.json` 约定；旧记录先转换并复核。原文修订后保留旧版本并建立新映射，不能让旧覆盖结果冒充新原文的覆盖结果。

### 原文核对规则

1. 先把台账逐段与原文对照，确认没有整段漏提取、误认集界或错置角色。后续“全部台账项都已覆盖”不能替代这一步。
2. 每条有声原文的分镜片段按最终播放顺序拼接，应恢复其锁定文本及标点；除来源换行与字段包装外，不做同义替换、去标点或语气词清洗。逐项核对说话者、集号、顺序、重复与缺失。
3. 核对对象必须包含已经写出的最终 `字幕/角色台词/旁白` 字段。使用长文本流程提供的脚本做精确字符串/区间对照，保存实际范围与文件版本；不能只检查计划映射后宣告成品通过。执行工具不可用时明确说明程序检查未执行。
4. 中英配对文本按原规则仅以英文计时、发声；中文和字幕参考仍有台账记录，但不算漏说。VO/旁白/现场对白分开标记；切到听者画面不改变原说话者。
5. 原文中两次出现的相同台词分别赋ID、分别保留；明确的前情回顾也按其实际来源保留。不能用去重算法删掉原文重复。
6. 动作按可见事件检查发起、接触/变化和结果；原文必需动作应有可定位的镜头承载，不能仅出现在剧情摘要中。场头和非有声参考只核对正确路由，不硬塞进声音或字幕。
7. 指定集任务只要求交付范围内完整覆盖，范围外记录为未请求；整本任务须全部请求集通过后才能标记整体完成。源文件本身缺失的集单独列出，不与漏生成混淆。

## 3. 全剧共用资料与连续场景状态

全剧共用角色ID、别名关系、外观/服装阶段、场景固定结构与道具身份。别名用于识别，不改写锁定台词中的角色标记。已知的后续揭示只用于规划，不能提前写进当前人物的认知、称呼、动作或情绪原因。

在详细分镜前执行 [global-asset-control.md](global-asset-control.md) 的有资产/无资产分流。共用资料增加资产ID、基准/变体、实际参考用途与可用性、来源事件、生效叙事时间及集场范围；人物身份母版不等于全剧同一衣装，场景母版不等于全剧同一时段。

道具归属、伤势、服装阶段、角色已知信息等可能跨场持续。为这些事实记录生效的原文事件、适用叙事时间线、变化来源和后续使用位置；换场本身不是重置依据。它们与某场戏的脚下位置、机位、暂时姿态分开管理。

区分两类场景标识：

- `location_id`：物理地点，例如同一客厅；复用稳定的门窗、台阶、固定家具等已有参照。
- `scene_instance_id`：同一叙事时间中持续的一场戏；可以跨组、跨集，或被其他场景暂时打断。回忆、梦境、平行时间线、重演、次日重返等另建实例，并标明叙事时间关系。

地点资产的几何/时段版本与连续实例分开引用：同一几何可有剧情所需的日版、夜版，同一日版也可用于多个日期的实例；复用资产本身不提供人物站位，同一实例仍须承接其最近有效末态。角色衣装与脏损、道具形态按各时间线的有效事件选择，回忆结束回到现在时恢复现在的有效版本。资产树按实际需求复用，不机械按集或按日期复制。

每个实例建立稳定的物理参照与方向定义，人物位置相对于这些参照记录。镜头中的左右、前后、前景/背景由机位推导；`中心锚点角色`只是该镜的描述与焦点组织方式，不重新定义场景坐标。单人镜头也要保留画外对手所在方向和相关世界状态。

同一扇门、同一桌椅使用稳定锚点名，相似家具需要能区分的落点。观察侧改变时只更新相机相对锚点的关系与屏幕投影，不重命名锚点；人物处于门内/门外、桌子靠窗端等物理关系保持，除非有动作或几何变化依据。人物状态和机位各自保存：先确定人物在哪里、胸口朝哪里，再选择相机的位置、朝向和拍摄侧，并推导画面左右、可见脸侧及画外视线。为拍正脸而无依据转身、转椅或镜像背景不成立；仅画面左右改变也不足以认定人物换位。

每次交接至少记录以下信息；必须在主体、景别、画幅、表演与光色的最终修复完成后更新为已核对末态，不能把修复前的草稿末态用于下游：

```text
状态版本、连续场景实例、地点几何版本、来源集/组/镜、状态依据及核对结果
人物：脚下/坐点相对固定参照的位置、站坐等姿态、胸口/肩线朝向、头部方向、视线对象、动作阶段、人物间距离/高低/遮挡关系、情绪余波
双手与接触：逐人左/右手的持物、接触对象及身体部位或空闲状态；抱扶时的承重/支撑点；需要继续保持的无接触部位
道具：持有人、持物手、所在位置、开合/激活/接触状态
场景与机位：已建立轴线、相机相对固定锚点的位置/朝向/拍摄侧、据此推导的画面关系，必要门窗/灯光变化
资产：当前修订、角色衣装/状态、地点几何/时段、道具形态及引用版本
本段初态、变化原因及源依据、本段末态、接续来源组/镜与状态版本、使用该状态的后续段
```

状态依据区分原文明确、已有已核对分镜、参考画面可见证据、为可拍摄性建立的推定。没有生成视频时称“分镜计划末态”，不要称“成片末帧”。缺少前集分镜时，可依据原文建立暂定初态并标明依据；不能声称与未知前集成片精确匹配。

只展开当前互动和后续动作依赖的身体细节，不给无关背景人物机械填表。身体、头部、眼睛分别判断；“看窗外”不自动改变脚下位置或胸口朝向，必要转头写出起止目标。手和身体部位的左右均为人物自身左右，可用“甲左手→乙右肩；甲右手空”记录接触；相关部位画外不可见时继承计划，实际画面未直接观察到的项与有已核对动作链支持的连续性推定分开记录，不能把推定写成所见。方向可用锚点关系表达，不普遍强加角度、米数或罗盘坐标。

### 交接判定

| 边界关系 | 初态来源 |
|---|---|
| 同一场戏直接续接，包括集末到下集开头 | 继承紧邻前段已核对末态；无新动作则不改位置、姿态或持物 |
| 切走后返回仍持续的同一场戏 | 读取该实例最近有效末态；中间插入其他组、集、回忆或场景均不重置本实例。仅按有依据的画外变化更新，不回到本场最初站位 |
| 同一地点但不同叙事时间、非连续事件或回忆 | 复用地点结构，另建实例；只承接有依据的持续事实，不机械沿用旧站位；同一连续事件内的新动作不构成另建实例的理由 |
| 连续关系无法判定 | 标明不确定依据；先做不依赖它的原文核对。影响关键动作匹配且无合理依据时，只询问这一具体关系 |

### 按实例维护接续链

工作记录按 `scene_instance_id` 索引各段的入态、变化、末态与接续来源，另存真实剪辑顺序。连续性复核沿同实例的接续关系进行，景别/主体滚动检查仍沿真实相邻镜头进行。一个组含多场时，细到场景段/镜头；不能只保存全局最后一组的状态。

每次起草返回段，先读取本实例最近已核对状态，再应用其后原文明示或已核对分镜支持的变化，最后生成本组机位与画面。没有走位依据时保留物理位置；有动作时承接动作结果。缺失中间状态则标记暂定依据，不拿场景母版中的初始人物位置补齐。并行生成沿同一已锁定计划状态派发，不能让各组自行重建站位；文字计划可并行，实际成片承接的验收仍依赖上游有效结果。

在每段工作记录中写明实际消费的来源组/镜、状态版本与依据类型，逐项对比“来源末态→本段入态”，只变更有动作/时间依据的项。没有有效来源时，按原文建立暂定计划、标出缺口并继续独立工作；不得报告该交接已通过。制作阶段同时保存计划与实际画面状态，失败或未检查的实际末态不供下游作为已验收起点。上游修订后按消费者记录使旧交接结论失效，并只复核受影响段；不靠重发同一段“保持一致”文字完成交接。

例：第1组中林岚从桌边走到门内一步处，周衡留在窗边；第2组切街道；第3组返回同一时刻的客厅。第3组承接林岚在门口、周衡在窗边及当时持物手，不恢复林岚最初的桌边位置。若第5组是次日且原文明示周衡坐在沙发、林岚从门外进入，则按新实例建立初态，继续复用门、窗、桌和沙发的固定布局。

### 起草前：先建立状态与必要变化，再编排镜头

所有模式的首次起草与修订均按以下顺序完成；使用现有实例记录，不新增用户可见字段。简单单场可以用紧凑记录，多组续接按实例保存。

1. **校准固定空间。** 按[全局资产管控第3节](global-asset-control.md#3-有资产流程查看适配绑定)先核对实际参考中的门窗、桌床、通路及相互邻接。没有参考时建立一致的文字布局并记录为拍摄设计。没有原文或已核对空间设计依据的罗盘方位不加入提示词，用“门框旁、床脚、书桌外沿”等固定参照表达；不明结构不补成已知事实。
2. **建立人物初态。** 从本实例最近有效状态逐项带入相关人物的落点、姿态、身体朝向、头部方向、视线、距离、双手占用和接触/支撑关系，包括参与互动的画外人物。保留未改变的项，再标出本段原文要求变化的项。新实例按原文另建初态，不机械复制旧场戏；计划状态与已检查的实际画面分别保存。
3. **列出必要变化。** 先从原文的动作和对话前后关系提取变化，再安排镜头。在内部记录每项的“对象／变化前状态／动作或时间省略依据／承载镜与完成点／变化后状态／后续使用位置”。动作尚未排镜时先定位源事件，排镜后补齐真实镜号。转头与全身转向、抬手与换手、手接触与物品已交出分别判断，不能用一种变化自动推导另一种。与当前故事无关的背景物不逐个建表。
4. **检查动作容量并简化调度。** 优先去掉分镜自行添加且无剧情作用的共持、反复换手、踱步或绕行；普通对白可以维持落点，以视线、转头和表情推进。保留原文必需动作、已有有效接触和已锁定上游状态，修订时不能为省事把它们删掉或静默改写。交接物品先确认双方可触达、支撑稳定和手臂占用：手递手交接写接收者接稳、原持有人松手及最终持有人；放到承放面时写落稳、撤手及物品落点；只安排实际动作所需阶段并留足时间。多项移动、交接与换场挤在同一短镜时，回到动作/对白时序重新分配镜头时间，不靠删结果、加速完成或无依据的画外动作消除冲突。遵守既定组界、音频和单镜限制；锁定条件内无可行解时明确未通过，不伪报可执行。
5. **由状态生成机位与镜头正文。** 人物的物理落点先确定，再计算所选机位中的画面左右、前后和画外视线方向。焦点轮换、景别与反打不重排人物。必要的交接、走位或空间重建使用能看清路径和接触点的镜头，按原分镜使用规则选择可见人数与格式；不机械让每组都以全景或多人镜开头，也不固定全场机位。关键动作把完成后的姿态、接触和物品落点写进承载镜正文，不能只写在组头。
6. **按变化复核并交接。** 对最终正文逐项查每次变化的依据、过程、结果和时间；再比对主体简表、组头初态、首镜、组内后续镜及下组入口。末态从最终动作结果推导，未变项继续保留，按实例传给下一消费者；执行[Audit 2B](review-mechanisms.md#audit-2b-scene-state-handoffs-including-nonadjacent-returns)。文字交接通过与实际画面通过分别报告，不能把重复写“保持站位”当作已消除生成偏差。

简例：林岚站在书桌外沿、右手垂持手机，随后转头看门口来人并接电话。变化链是“脚下落点与站姿保留；视线转向门口；铃响后右手抬手机至右耳”。换成她的单人镜时，仍把书桌关系和门口对象方向写入画面简介；不另添坐床、走到窗边或换手。若是放下文件，承载镜应写出“文件落稳于桌面、手离开文件”，下一段再使用“文件留在桌上”的结果；原文另有离开动作时才继续安排人物离开。

### 从状态底稿编译执行输入

完整状态与依赖版本保存在项目工作记录，当前组/镜的实际提示词按以下内容编译，沿用既有交付字段，不另塞审计表：当前所用参考的职责与作用段；已展开的相关入态；机位与推导出的画面关系；有序必要动作及明确终态；原锁定音频时序和所需表演/光线。若段内换场，按各自入口分别编译，不让后场状态污染前场。

每镜确定一个主要可见任务，必要的准备、支撑建立和完成结果可以同镜。仅删去无剧情作用的动作与重复静态描述，不用删关键初态、音频或动作结果来缩短输入。身份图不承担剧情姿态，画外角色不因省略外貌描述而失去位置。正文必须可独立使用，但不复制全剧台账或要求生成器自行解析本地状态ID。

在反打、续场首镜和细节裁切可能冲突的镜头，按[从站位推导可见画面](shot-space-checks.md)把相机位置转成可核对的胸前/侧身/背面、实际背景、可见人物集合和动作覆盖范围，再从这幅画面反查状态是否成立。用正文中的具体结果支撑“朝向不变”，不靠镜头标签或组头状态替代这一步。

简例：甲坐靠窗椅，胸口朝桌对面的乙，右手压住桌上信封、左手空；听见门响只转头看门，坐点与胸口朝向不变。反打改从门框侧拍时，先保留这些事实，再推导可见脸侧和画外乙的位置。不可为了让甲再次正对镜头而转动椅子。

### 每组可独立使用的空间初态

在既有 `场景与环境状态` 中用一段自然语言完整展开本组入态；以下是必需内容清单，不新增用户可见审计字段。多场组分别在该段对应镜头展开，不能将后一个场景的初态混入首镜。

| 内容 | 写入实际提示词的要求 |
|---|---|
| 固定参照与方向 | 使用同一套门、窗、固定桌床、通路等名称，交代足以区分人物所处端/侧的布局；方位是原文信息还是拍摄设计留内部记录，不随镜头左右改名 |
| 人物与道具初态 | 对本段参与互动、接触或出入画的每个人，写出相对固定参照的脚下/坐点、身体与头部朝向、视线对象、姿态和动作阶段；写明左右手占用、相关接触/支撑及必要距离、高低、遮挡关系。方向一致时可合写；暂在画外的对手也有确定位置，不因未入画而消失 |
| 轴线与机位 | 交代已建立的人物轴线和摄影机所在物理侧；依据该机位推导画面左右、前后及画外方向。中心锚点角色轮换不改变场景参照；反打可以改画面投影，不允许无动作地换位或镜像场景 |
| 动作起点与结果 | 首镜从本段初态开始，相关镜头写清走位起点、路径、接触与终点；动作完成镜交代结果，后续未改变的项继续有效，据此保存本段末态。无需为了记录末态让所有人重新同框；不将动作完成态提前放入首帧 |

单人镜头仍只用 `画面简介`：分号后写人物与固定参照的关系、相关画外对象方向及动作。多人镜头在三段式字段中落地同一初态。只写“客厅内”“A左B右”“保持站位”或仅在全局连续性里记录，均不足以让该组独立使用。必要距离可用“门内一步”“隔桌相对”等可拍关系，不无依据增加精确米数；与当前动作无关的路人无需逐个建站位。

源文、已核对镜头或可见参考不能确定的关键位置先标为未决；非剧情性的机位/朝向可作一致拍摄设计并记录依据，不能把推定伪称成片事实。只缺图片时可完成文字初态，实际图像/视频验收按[全局资产管控第3A节](global-asset-control.md#3a-站位参考首帧与实际画面承接)处理。

人物、道具、机位分别更新；换焦点、切反打或改画幅不能让人物瞬移、换手或改掉已锁定的行走路线。机位选择须服从当前轴线；剧情要求越轴或重新建立空间时记录可见的过渡依据。

如果一个组包含换场，分别记录每段所属实例的末态与入场态，不能把整个组压成一套人物站位。每组 `场景与环境状态` 和相应镜头要用自然语言写出实际需要的初态、画外方向与变化；不能只写“同上”“继承前集”或让生成器自行查工作台账。

需要并行起草时，先确定依赖关系与可用的交接状态。同一连续场景的下游不得独立猜测初态；若使用暂定状态，待上游核对后重审下游。重写前段导致末态变化时，沿依赖关系检查后续使用：脚下位置等场内状态可在原文重新建立的新实例处结束继承；道具归属、伤势、服装和知情等持续事实须跨实例追踪，直到状态重新一致或原文明确重新确立该事实，不能仅因换场停止重审。

## 4. 逐集生成与边界

1. 按用户指定范围及原集序选择下一集，使用已完成全文读取的索引，再按长文本流程加载该集当前批次的精确原文、必要上下文、人物信息、场景母版、入场状态和前两镜摘要。超长单集不必每批重新装入全文；未请求的中间集只提取相关原文依据，不生成其完整分镜。
2. 在当前集内执行主 skill 的估时、分组、镜头编排、表演和光色流程。各组保存初态/末态，核对后推进；不要到全剧末尾才开始检查交接。
3. 每集重新从第1组、目标 `00:00` 开始；镜号沿用现有组内编号。内部以复合ID避免重号混淆；同一集跨批输出时接着原组号和目标时间，不重新从头计数。
4. 原文集界不可为凑15/30秒、满足景别变化或切换主体而移动。组边界修复只能在同一原集内移动完整单元；原文明确跨集延续的动作以各集实际记载分别承载，空间状态跨集交接。
5. 本集最后剩余内容不足目标组长时，允许一个按真实台词与动作时长结束的尾组，标题仍报真实总秒数。此例外只放宽最后未满组的组总时长，逐镜上限、短镜有声条件、原文和完整动作规则仍适用；不得借下一集台词、编造情节或无依据拖时。若平台明确要求所有组精确时长且无法兼容，说明具体冲突，不假报时长或吞掉尾段。
6. 各批完成程序台词检查与内容复核后保存，再对本集实际汇编成品重新核对覆盖、组内/跨组状态和原集边界，更新检查点并继续下一请求集。用户要求整本时，一集是汇总保存单元，不是默认停止或再次请求批准的理由。

组内相邻两镜标准景别默认不同；换人物、明显换角度、真实过肩正反打、独处或情绪高潮可按源文与镜头第5B节逐对核实豁免，小幅角度变化本身不豁免。跨组末/首镜仍须不同，不沿用组内豁免。景别与三镜主体规则均按真实原集顺序中的相邻镜头检查；集号或输出批次重置不应隐藏待审边界，移动组界本身不构成豁免依据，须按调整后的组内/跨组范围重新核对。只选第1、3集时，两份成品不能被当作直接相邻；跨越未提供或未生成镜头的边界标为不可核对，不把中间内容删掉后拼接滚动窗口。同一场戏的状态依赖仍可跨越这种缺口，按原文与已核对实例状态判断，不能与剪辑相邻关系混淆。

跨集修复不能跨原集搬台词、改变继承状态或擅改已交付成品。读取实际相邻前集末镜景别和末两镜焦点；缺失的历史镜头标为不可核对，不捏造。若规则无可行解，记录具体冲突与影响，不以“审核通过”掩盖失败。

## 5. 保存、输出与续作

记录与成品放在当前剧本任务的工作/输出位置，遵守宿主目录规则，不把任何具体剧本、人物台账或进度写进通用 skill 安装目录。

有文件工具时，保存原文快照、任务清单、原文/分镜映射、场景状态和续作记录；每集成品单独保存。文件名按原集号与修订区分，复用已有检查点前核对来源，不覆盖不同原文任务。工作台账与可直接使用的视频提示词分开；不要向每个组中追加JSON、审核表或全剧摘要。

全剧最终交付须按[全局资产管控第6节](global-asset-control.md#6-全剧最终交付人物场景道具提示词汇总)同时提供一份独立的人物、场景、道具提示词汇总，包含最终所需各版本的完整正文及实际使用范围。前期资产树/卡或绑定表不替代最终汇总；资产相关成品修订时同步更新汇总。最终回复同时链接全剧提示词与汇总，已有交付索引/压缩包也包含汇总。

默认按集处理和保存，并继续完成全部请求范围；用户希望聊天内逐集查看时按其节奏输出。单集过长可在完整组结束后保存和分批续写，不能在台词片段、动作单元或字段中截断。若确有输出/执行限制导致本轮未完成，保存可恢复的检查点，并准确报告已完成集组、剩余范围和下一位置，不用“后续同理”代替成品，也不声称全部完成。

续作先核对原文修订、用户参数与已交付内容：

- 未变化：从下一未核对单元继续，保留同一集的组号/时间和各实例状态。
- 原文或上游分镜变化：标记受影响的映射与后续状态需要重审；重新核对后更新版本，保留不受影响的成品。
- 资产补充或版本替换：按原资产依赖定位受影响集组；检查衣装、时段、道具状态和参考用途，几何改变时重算站位/机位并追踪下游。文字设计被图片替换后不得直接继承旧的匹配通过结论。
- 只有剧情摘要、没有旧台账或旧成品：说明可恢复范围；可从原文重建计划，但不能据此保证与未知的既有镜头接续。

无可用持久文件工具时，把可恢复的进度和最小交接记录作为明确分隔的任务记录提供，置于视频提示词之外；不要承诺下一次会自动记得未保存内容。

## 6. 完成条件

只有以下条件均满足，才可报告请求范围完成：

- 实际输入范围已核对；每个请求集的原文单元与成品对应，主声轨无缺失、额外重复、改写、错角色或越集挪用，必需动作有镜头承载。
- 每集编号、组号、实际时长与成品范围一致，尾组例外有据可查；所有已生成组具备完整格式，没有用梗概替代后段分镜。
- 直接续接、隔场返回和新时间实例均使用正确状态来源；前景/焦点/画幅变化没有改写实际站位；不能核对的历史边界已明确标记。
- 既有逐镜与跨组审核完成，最终改写后的文本和状态也已重新核对。
- 前置资产树/绑定表和当前版本使用关系已交付，关键资产/剧情冲突已处理或明确影响范围；文字设计完成与实际图片可用/平台已绑定分别报告。
- 全剧最终交付时，独立的《人物场景道具提示词汇总》已与最终实际分镜和资产版本完成覆盖/一致性核对，并同批交付；不能只有名称、链接、旧卡或未展开的差量，也不能只汇总最后一批。
- 成品与检查点已保存或明确交付；指定集任务称“指定范围完成”，输入不全时称“已提供范围完成”，不夸大为全剧完成。

原文覆盖与状态检查的完整结果留在工作记录。最终反馈只需交付成品位置、实际完成范围，以及仍需处理的具体问题。
