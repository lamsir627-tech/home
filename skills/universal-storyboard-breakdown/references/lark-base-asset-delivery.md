# 飞书 Base 资产交付

将已核对的资产汇总同步到飞书多维表格。继续遵守[全局资产管控](global-asset-control.md#6-全剧最终交付人物场景道具提示词汇总)与[最终交付格式](final-delivery-format.md)：本地全剧提示词和独立完整汇总照常交付，本流程不重拆分镜。

## 1. 触发、依赖与项目绑定

只有用户明确要求同步，或当前项目有覆盖本次目标与内容范围的已授权绑定，才写飞书。沿用会话中的有效授权，不在例行交付、分批或重试时重复询问；用户的新要求可收窄或撤销授权。模板参考、已有访问权限、安装技能本身均不等于同步授权。没有授权时可读取模板并准备本地映射与差异，不写入；不因本流程创建定时任务或后台自动同步。

按当前会话技能目录定位并读取实际安装的依赖：

- [lark-base](../../lark-base/SKILL.md)：解析链接、定位 Base/Table、读取字段与记录、按真实字段类型同步、检查写入结果。
- [lark-shared](../../lark-shared/SKILL.md)：CLI 入口、身份、认证、scope/ACL、返回契约及真实审批阻断。保持任务所需身份，按其流程解决认证，不能通过换身份绕过权限。

这些依赖链接以本技能在已安装技能目录中的位置解析；本技能经 junction/symlink 指向独立 Git 仓库时，依赖不随仓库分发，须以当前技能目录给出的实际 `SKILL.md` 路径读取。路径变化时重新定位，不猜 CLI 参数或复制一份过期认证流程。依赖缺失或认证阻断时继续完成本地文件、映射和可核对的同步计划，准确说明远端未完成范围；仅在实际缺口需要用户处理时提出具体事项。

将绑定保存在**剧本项目本地工作目录**，例如 `work/integrations/lark-assets.local.json`，而非技能/Git 仓库。记录项目稳定标识、目标/模板 URL、实际资源坐标、分类与字段映射、授权来源和范围、本地资产修订、版本键到远端记录 ID 的映射及最近验收状态。凭据交由 lark-shared 管理，不写入绑定、日志或提示词；私有剧本、正文数据、模板 URL、账号信息和项目资源映射均不提交技能仓库。文件名后缀不构成排除提交机制，保存位置必须正确。

## 2. 先读真实模板与目标

按 lark-base 解析用户链接，确认它是目标 Base、模板、某张表或视图；视图不等于完整表范围。读取真实表结构、字段 ID/类型、可写性、选项及目标已有记录。用户要求“参考模板”时，不把模板原件自动当成写入目标；结合既有项目绑定和用户要求确定目标，需要副本时使用其已授权创建范围。

在项目配置中建立本地信息到实际字段 ID 的映射；以下是应保留的信息，**不是预设模板字段名或类型**：

| 信息 | 同步要求 |
|---|---|
| 项目与资产身份 | 项目标识、稳定资产 ID、明确版本；用于区分不同剧本与同名资产 |
| 分类与名称 | 保留人物、场景、道具分类；遵循模板已有分表、分类字段或选项 |
| 提示词正文 | 每个版本独立完整可复制的正文，含该版本所需不变量与状态 |
| 使用范围与来源 | 实际集/场/组/镜或源事件范围、设定依据及对应本地修订；尚未拆镜不得编造镜号 |
| 状态与参考 | 区分文字设计、参考图可用、平台已绑定、已核对/待核对；只记录真实参考与可用状态 |

单一表可沿用现有分类字段，多表模板可按三类分别映射；不能为统一外观擅自搬表、改选项、覆盖公式或重命名模板字段。若模板不足以容纳完整正文、稳定匹配信息或必需元数据，先完成可行映射和具体差异；在授权范围内补足结构，否则只就所需具体结构变更确认。不得静默截断正文、只上传摘要/链接、或写入无关字段冒充同步完成。

### 三表模板映射示例

以下命名来自已读取模板，可用于用户已选择“新建独立资产表，沿用参考格式”的项目。它只展示如何保留原模板并补齐交付信息，不强制其他模板同名；每次仍需读真实 schema，并把实际字段 ID、类型及 Base/Table/View 坐标保存在本地配置。

| 分类表 | 已有正文与范围字段示例 | 已有制作字段示例 |
|---|---|---|
| 人物 | `人物名`、`出现集数`、`使用场景`、`提示词` | 附件：`三视图`、`定稿`、`主视觉`；反馈：`反馈意见`、`反馈意见2`；`父记录`自关联 |
| 场景 | `场景名`、`作用集数`、`提示词` | 附件：`场景主图`、`场景衍生图`、`修改图`；`反馈意见`、`文本 5`；`父记录`自关联 |
| 道具 | `道具名`、`提示词` | 附件：`道具资产图`；`反馈意见` |

完整正文写入实际 `提示词` 字段，名称与使用范围分别映射已有对应字段。在已授权的新表结构中，可补充 `资产ID`、`版本`、`适用组镜`、`用途与依据`、`来源定位`、`镜内时点`、`参考与状态`、`项目`、`内容校验` 等字段；其中 `内容校验`保存本地完整正文的校验摘要，仍须读回正文计算对比，不能只比较这个可写值。没有现成附件时附件列留空，不能把文字设计标成图片定稿；不捏造反馈或父子关联。既有记录的用户附件与反馈继续保留。

## 3. 一版本一记录与差异同步

输入以本次已核对的本地汇总及实际版本使用表为准。核对三类版本集合与完整正文，复用既有语义审读；有资产相关修订时只重审受影响状态。明确交付范围，不能把初期草案当全剧最终资产。

- 使用稳定的逻辑键，例如 `项目标识 + 资产 ID + 版本 ID`；已有资产版本 ID 本身唯一时直接沿用。显示序号、名称、行号、同步时间不作唯一键。同一版本跨多集只保留一条并合并准确使用范围；年龄、衣装、伤势、场景时段或道具形态等互斥版本分别记录。
- 同镜发生状态变化时保留变化前后阶段的真实适用范围，不把后态绑到组首/镜首，也不把完整版本正文混成互斥状态。映射沿用已核对事实，不能为远端行数相等增删资产版本。
- 先读完目标中本项目相关记录的全部分页，确认筛选范围；仅看到第一页、某个视图或缓存映射不算排重。结合逻辑键与本地记录 ID 映射验证目标身份。若旧行缺少身份信息，先核对分类、版本、正文和来源建立可信映射；歧义不能靠名称猜测或追加重复行解决。
- 形成新增、差异更新、无变化及冲突清单，授权已覆盖时直接执行。不存在的版本创建记录；已存在的同版本只更新发生变化且归本次同步管理的字段。保留用户维护字段、附件和无关记录，不整行覆盖；保留不在本次范围或已不使用的旧记录，不擅自删除、清空或改为废弃状态。
- 按 lark-base 实际批量限制分批写入；同一表写入顺序执行，保存成功返回的记录 ID、失败项与本地修订。无变化项不重复写。响应不确定或中途失败时先读回核对，再补缺失项；不盲目重放创建请求。

## 4. 读回后才报告完成

完成本轮相关写入后统一读回验收；遵守 lark-base 的异步生效说明，必要时有界等待后重读，不能用逐项即时读取暂不可见的结果认定丢失并再次创建。仍未确认时报告“写入已返回，读回待确认”，不宣称全部同步成功。

按本项目、本次范围逐项核对：

1. 远端逻辑键集合与本地待交付版本集合一一对应，分类计数一致且无重复；排除模板样例和其他项目，保留的历史行另计。
2. **读回所有本次版本的完整正文**并与本地逐字比较，保留换行与空白；若接口返回富文本，按实际返回协议还原正文后比较。只验证 API 成功、记录数、标题、摘要或少量抽样不够。
3. 核对真实使用范围、来源、状态及分类，确认新旧版本没有相互覆盖；写入结果中的失败/忽略字段必须处理或列明。

保存本地验收记录：目标链接和资源范围、本地修订、预期/实际分类计数、新增/更新/无变化/失败数量、正文比较结果及未解决项。最终同时提供本地全剧与资产汇总链接、可用的飞书目标链接和实际同步结果；本地已完成但远端未验收时分开说明，不能把本地文件生成当成飞书交付完成。
