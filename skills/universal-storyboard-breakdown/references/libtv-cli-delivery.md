# LibTV CLI 分镜交付分支

用于把已核对分镜转换为 LibTV 画布上的分镜表。沿用主技能的源文、语速、组长、逐镜上限、主体轮换、景别切换、动作与对白时序、资产及连续性规则。用户只要求调整技能时不转换旧剧、不导入远端。

## 1. 入口与版本

触发示例：“按 LibTV 分支生成，30秒一组，真人风格，9:16”“将已完成分镜用 LibTV CLI 导入这个画布”。前者交付本地导入包；后者包含向指定画布写入的授权。复用本任务已确认范围与目标，仅缺少真实目标或认证时处理对应缺口，离线整理可继续。

本分支依据 **2026-09-15 核验的官方 CLI 1.1.3 文档**，不是永久固定版本：

- [官方发布信息](https://api2.liblib.art/api/www/landing-activities/getById?id=240)的发布内容提供版本与下载地址。
- [官方 1.1.3 文档包](https://liblibai-web-static.liblib.cloud/cli/1.1.3/libtv-cli-skill.zip)：重点读取 `commands/node.md`、`node-types/script.md`、`node-types/storyboard.md`、`commands/script.md`。

实际执行前检查可用 CLI 及 `libtv --version`、`libtv node --help`、`libtv node create --help`。若当前版本改变字段或语义，依据当前官方文档和真实帮助更新映射，并记录版本。下载资料不等于已安装或验证 CLI；入口失效也不能靠第三方示例推断协议。

`storyboard` 是画布分镜表类型，`script` 是脚本类型，两者共享 `rows` 结构。默认创建 `storyboard`；既有目标为 `script` 或用户明确需要该类型时沿用。已有节点更新不传 `-t`。这不是 LibTV IM 自由文本生成入口，也不是 Blender 图片/视频素材上传入口。

## 2. 保留分组与生成内容

- 默认一原分镜组对应一个节点，一实际镜头对应一行。按源集、组、镜顺序组织；30秒组不能写成一条30秒行。保留短尾、原始小数时长及组界，不合并不同集。
- 本地稳定标识用 `E001-G001` / `E001-G001-S001`；节点展示名可用“项目短名-E001-G001”。不要把内部标识、核对结论或文件路径写进生成提示词。`shotNumber` 由平台按节点内行序处理，本地镜号不依靠展示序号追踪。
- 从最终 Markdown 和已核对资产版本派生行，不调用模型重新生成分镜表。每行应包含独立可用的具体人物、场景、机位与道具状态；不能只写“沿用上一组”或资产 ID。人物图未提供时保留文字设计、参考图 URL 留空。
- 派生每行前，从本地实例接续链定位该镜起点：同组后续镜承接已有动作结果，隔组返回查该实例最近有效末态，不取另一场景的最后一行。将固定参照、人物相对位置/朝向/视线、相关画外对象、持物手与摄影机物理侧展开到实际图像/运动提示词；节点名称、`sceneTags` 或无人场景图不能替代站位内容。实例ID、状态版本与来源组/镜保留在项目工作记录，不作为虚构平台字段写入 `row`。
- `imageGenerationPrompt` 写**本镜起始瞬间的一张静态画面**：画幅、质感、景别/角度、真实可见人数、站位/朝向/视线、当时衣装伤势、持物手和环境。运镜和事件完成后的状态不放在静态首帧里；不能提前出现后续受伤、开门、破损等结果。
- `videoMotionPrompt` 写**该镜完整动态过程**：原时长、机位运动、人物动作、表演、发声时点、反馈与尾态；沿用原组动作连续性。说话情绪落实到说话者的可见动作和声音，不给画外声强加可见嘴型。
- 先做再说：初帧是动作前态，运动提示写动作完成后发声；边做边说：标明哪段动作与哪段发声重叠；说完再做：初帧保持发声前的原位置/道具，运动提示写发声结束后才行动。混合情形保留分阶段次序，不能统一套用“边说边做”。
- `dialogue` 专存锁定音轨，以 `源说话者: 原文片段` 表示，每段一行、保持顺序和源空白；静默写 `无`。中英配对仅写英文发声内容。情绪与“先做再说”等说明写其他字段，不插入原文。运动提示可描述发声时点；确需重复台词时从同一锁定片段复制，不翻译或改写。

## 3. 官方行字段与本地交付包

只有每镜 `row` 内的字段进入 LibTV `rows`。外层是**本技能定义的本地交付协议**，不是 LibTV 原生文件上传格式。

| `row` 字段 | 来源与约束 |
|---|---|
| `durationSeconds` | 原镜秒数，number，保持精度。官方文档仅称“范围约1.0–15.0”，不能当作已验证硬上限；主技能的3.5/5秒限制仍适用。实际拒收时报告具体镜头，不擅自取整或重定时 |
| `plotDescription` | 原镜完整情节与可见画面，包括关系镜头的中心锚点、机位和动作结果 |
| `characters` | 实际可见人物数组，含前景肩背；每项为 `characterName`、`characterDescription`、`characterImageUrl` 三个字符串。画外说话者仍在对白里，不冒充可见人物；无人道具镜用空数组 |
| `shotSize` | 原标准景别。官方列举特写/近景/中景/全景/远景，未声明严格枚举；不要为了凑枚举私改原构图 |
| `characterAction`、`emotion` | 原动作/表演定位、源文支持的情绪，均为字符串 |
| `sceneTags`、`lightingAndAtmosphere` | 具体地点时段/几何环境与实际光色，均为字符串，不只写资产编号 |
| `audioEffects` | 现场声和环境音字符串；平台有此字段不构成添加 BGM 的依据 |
| `dialogue` | 严格锁定的发声音轨字符串，多个片段用真实换行 |
| `imageGenerationPrompt`、`videoMotionPrompt` | 分离的静态首帧、视频运动完整提示词，两个字段均不可为空 |
| `videoReference`（可选） | `{ "referenceFrameImage": "真实图片URL" }`，是镜头参考帧图片，不是视频 URL；无参考图时省略 |

新增行省略服务端 `id`、`hiddenUuid` 和显示 `shotNumber`；不手设节点 `title`、`linkedImageGroupId` 等服务端字段。更新时保留读回的行身份及已有素材关联，见第5节。

在项目输出目录交付 `libtv-handoff.json`，结构如下；下列只示意一镜字段，实际包必须包含所选 Markdown 的**全部**组镜：

```json
{
  "schema_version": 1,
  "platform": "libtv-cli",
  "cli_docs_version": "1.1.3",
  "aspect_ratio": "9:16",
  "style": "写实短剧质感",
  "groups": [{
    "group_id": "E001-G001",
    "episode": 1,
    "group_number": 1,
    "duration_seconds": 3.0,
    "node_name": "示例-E001-G001",
    "node_type": "storyboard",
    "negative_prompt": "",
    "shots": [{
      "shot_id": "E001-G001-S001",
      "action_dialogue_order": "先做再说",
      "row": {
        "durationSeconds": 3.0,
        "plotDescription": "平视中景，固定机位，焦点为林岚；她独自站在桌旁，将右手中合着的信封放到桌面，放稳后抬眼说话。",
        "characters": [{"characterName": "林岚", "characterDescription": "成年女性，黑色短发，灰色衬衫", "characterImageUrl": ""}],
        "shotSize": "中景",
        "characterAction": "放稳信封后抬眼发声",
        "emotion": "克制而坚定",
        "sceneTags": "白天室内，木桌靠窗",
        "lightingAndAtmosphere": "窗侧柔和日光",
        "audioEffects": "信封接触桌面的轻响；室内底噪",
        "dialogue": "林岚: 看这个。",
        "imageGenerationPrompt": "9:16竖屏，写实短剧质感，平视中景；黑色短发、灰衬衫的成年女性林岚独自站在靠窗木桌旁，右手仍握着合拢的信封，手位于桌面上方，目光落向桌面；窗侧柔和日光。画面无字幕。",
        "videoMotionPrompt": "3.0秒，9:16竖屏，写实短剧质感，固定机位中景。林岚先将右手中的合拢信封放稳在木桌上，随后抬眼、以克制而坚定的语气说出本行锁定台词；说完保持视线，信封留在桌面。画面无字幕。"
      }
    }]
  }]
}
```

`action_dialogue_order` 取 `先做再说 / 边做边说 / 说完再做 / 混合 / 无对白 / 仅对白`，是核对元数据，不上传为自造行字段。`negative_prompt` 保存原组完整负面提示词；没有专门负面词时为空。当前行 schema 没有独立画幅、模型、负面词字段：画幅/质感需落实在提示词内；独立负面块保留在母版和交付包，后续生成时仅映射到所选模型真实支持的参数。高精度3D的原始正/负向风格约束均须保持，通用母版的固定块仍按原位置与次数保留；单镜独立投喂时展开该行所需的完整正向风格正文，适配副本不回写母版。不要把负面块塞入正向提示词冒充生效。

## 4. 导入前核对

先完成主技能的源文与实际 Markdown 核对，再运行以下本地检查；`--storyboard` 后列出本次所有实际交付文件，按播放顺序排列：

```text
python verify_libtv_handoff.py --package <项目目录>/libtv-handoff.json --storyboard <第1集.md> <第2集.md> --report <项目目录>/libtv-handoff-check.json
```

脚本位于 [scripts/verify_libtv_handoff.py](../scripts/verify_libtv_handoff.py)。它检查包结构、字段类型、组镜一一对应与顺序、原秒数和锁定对白，保存实际文件摘要。它不替代源文核对、动作时序/静态首帧/人物版本的语义复核，也不证明真实 CLI 接受载荷。画幅、风格、负面词及资产版本还需对照母版审阅。

另按[镜头复核 Audit 2B](review-mechanisms.md#audit-2b-scene-state-handoffs-including-nonadjacent-returns)核对每行静态起点、运动结果与同实例上下游，包含跨节点/非相邻组。`semantic_verified=False` 的结构报告不能称为站位验收；参考字段通过字符串检查也不证明图片正确。若 `videoReference.referenceFrameImage` 已提供，实际查看并记录它对应的实例、状态、机位及用途；不适用当前镜首态的旧末帧不能冒充匹配首帧。

导入前核对本地 `group_id → node_name/type → shots`，并保存实际项目 UUID、返回 `nodeKey`、远端行身份、源文件与载荷摘要、状态/错误于项目目录的 `libtv-import-map.json`。资产版本与节点/图片的真实绑定可另记同目录；无绑定不得编造 URL。真实项目、剧本、认证或画布 ID 不写入公共技能仓库。

## 5. CLI 写入、重试与读回

已获授权且目标、认证明确时继续执行，无需每组重复确认。使用显式画布 UUID 定位；CLI 的 `projectUuid` 指画布，`workspaceId` 指容纳画布的项目，两者不能混用。还须只读核对当前工作目录 `.libtv/project.json` 的默认 `groupNodeKey`：即使指定 `-p`，省略 `-g` 仍可能套用旧分组，限制列表/查询/更新并改变新节点归属。默认在无分组绑定的专用导入目录运行；目标确需普通分组时显式传已核对的 `-g`，不静默改掉用户原目录绑定。创建前的整画布排重列表也在无默认分组的范围读取。

官方1.1.3支持的命令形态是：

```text
libtv node create <唯一节点名> -t storyboard -p <项目UUID> -u rows=<完整JSON数组>
libtv node <已验证nodeKey> -p <项目UUID> -u rows=<完整JSON数组>
libtv node <已验证nodeKey> -p <项目UUID>
```

这些是参数结构说明，不能直接把尖括号当真实值执行。读取本地 JSON 后，只取该组 `shots[*].row` 序列化为 JSON 字符串，作为单个 `rows=...` 参数传入。推荐使用原生 CLI 可执行文件与 `subprocess.run([...], shell=False, stdin=subprocess.DEVNULL, ...)`，正文不拼进 PowerShell/cmd 命令，也不写入 shell 插值表达式。

**传输边界：**当前官方文档没有 `@file`、`--import` 或 stdin JSON 写 rows 的协议；stdin 是上游 `nodeKey/newNodeKey` 连线输入。读取文件再传 argv 仍受宿主命令长度限制。先测量最终参数串的实际转义长度，Windows 按 UTF-16 命令行长度预检并留余量；不要使用 `.cmd` 包装器再拼长正文。超限时可按连续镜头将同一逻辑组分为 `-part01`、`-part02` 等**独立节点**，在本地映射记录原组、原镜与各段顺序/秒数，原导入包和母版组界不变。逐段仍传完整 rows；单镜也超限或传输能力未确认时保留离线包并报告具体阻塞，不能删内容或声称导入完成。

- 创建前读取目标节点列表并核对名称/身份。本项目映射对应的节点可更新；同名却身份不明时先解决目标冲突，不能覆盖他人节点或盲目重建。
- **`-u rows` 是整数组替换。** 更新前读回全节点，保存其行 `id`/`hiddenUuid`、素材关联和用户维护内容，并与最近一次成功导入的内容比较。只替换本次管理且无冲突的内容；保留范围外行和字段。不是追加接口，不能对同一节点分批写几行，否则前批会丢失。新增包不带行身份；更新载荷合并真实读回身份后另存，不把伪造 ID 写回导入包。
- 每次成功写入保存节点 ID；返回不确定或中断时，先读回该明确目标并比较，再决定补写，不能盲目重放创建。远端人工修改与本地更新冲突时保留两版和差异，解决后再覆盖冲突字段。
- 逐节点读回本次管理的**全部行**，核对行数、顺序、逐镜秒数、完整对白及全部已写提示词/角色等字段；只忽略平台补充的身份和展示序号。记录期望/实际与不一致项。只看退出码、标题、节点数或抽样内容不足以声明验收完成。

纯导入命令不带 `--run`、`--run-all`；不调用 **`libtv script storyboard`**，该命令会派生图片节点并逐张生成。后续确有媒体生成请求时再查询实际模型 schema、画幅/时长/负面词参数和参考资产，按对应授权执行；不能把分镜行导入成功等同于图片或视频生成成功。

进入已授权媒体制作后，按[全局资产管控第3A节](global-asset-control.md#3a-站位参考首帧与实际画面承接)派生/检查对应首帧、核实真实绑定，并逐组检查实际首尾、切点两侧及动作关键帧。按[第3B节](global-asset-control.md#3b-实际生成输入版本)保存生成输入记录：实际使用已有视频节点时，在运行前重新核对其完整提示词、有序参考及有效模型参数；使用分镜行时记录实际行身份和消费载荷。早先导入读回通过不证明当前生成仍使用该版本；`generation-input-manifest.json` 与导入映射按节点/行和任务ID关联，不写成虚构平台字段。前组生成偏差不自动成为后组的新站位；纯导入任务将媒体检查记为未执行，照常完成本次导入与读回范围。

## 6. 交付状态

LibTV 分支额外交付 `libtv-handoff.json`、本地核对报告和简短使用/导入结果说明。全剧原 Markdown 与独立“人物场景道具提示词汇总”照常交付；飞书资产同步仍只按原授权绑定执行。

状态分别报告为“导入包已核对”“已写入、待读回”“已读回验收”或具体失败范围；有媒体生成时另报其实际结果。远端完成时提供目标链接、原集/组/镜计数、实际节点数（包含传输拆段）和未完成项；仅离线完成时提供文件，不伪造画布链接、节点 ID 或导入成功声明。
