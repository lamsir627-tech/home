# (新)30S拆分镜

将已提供剧本转成可独立生成、跨组连续、原文可核对的视频分镜。默认中文交付，15秒一组、写实短剧质感；用户可指定30秒、高精度3D、语言和画幅。使用完整剧情理解来选择镜头，用可追溯证据约束台词、人物知情、道具和空间状态。

## 执行原则

- 用户当前要求与同一任务已确认的约定优先于本技能默认；只完成所请求阶段与范围。用户中途补充要求时保留已完成工作，定位受影响状态并继续。
- 主模型负责全剧理解、叙事取舍和最终整合；脚本负责确定性文本核对。更强的长上下文能力不等于原文已读、不遗漏、永久记忆或下游视频可控性保证。
- 按依赖组织工作，不要求逐条展示思考过程。先锁原文与源范围，校准场景并建立人物初态和必要变化，再安排时间与镜头，最后细化表演/光色并核对状态变化；无依赖的分析可合并或并行。
- 每段实际消费一份有来源版本的场景状态，分开更新身体、头部、视线、双手/接触与机位；从状态派生该段可独立使用的提示词。已进入媒体制作时，输入版本、首帧、动作与跨段交接分别验收，未通过的画面不传作下游有效状态。
- 短单集可用一份紧凑工作记录；长剧按自然场景、连续状态与可完成输出量调整批次。新剧本默认走[两轮交付](references/two-round-delivery.md)，首轮交齐图像提示词和回传清单后等待尚缺的参考图。
- 当前模型名、工具与上下文额度以运行环境为准。本技能不切换模型、不修改配置，也不把 API 公布额度当成当前 Codex 会话可用额度。

## 本地 RAG 检索

开始分镜制作、参考分析或修订时，用当前阶段的具体问题检索本地知识库。PowerShell 可从任意工作目录运行。

```powershell
& 'E:\Wl rag\project\rag\skill_rag.cmd' query --skill universal-storyboard-breakdown --intent rules --json '隔组回到同一场景时，如何承接人物站位和朝向？'
```

- `rules` 查本技能规则，默认不重排。按需用 `cases` 查分镜案例、`photography` 查写实光影摄影案例、`wiki` 查概念与综合资料。
- 核对 `binding` 中的技能、意图、知识库和重排状态。按命中的 `path`、`source`、`lines` 打开原文件核对上下文。应用规则时以当前技能的明示要求和本次任务约定为准，仍须阅读用户剧本与必需参考并执行分镜校验。引用 Wiki 涉及硬性规则时，沿其引用回读原文。
- 查询无结果时记录无匹配。入口、索引或模型失败时说明原因，直接读可用参考继续。查询和来源记录放在工作稿中。

## 参数与缺失信息

短剧视频分镜提示词的默认技能与交付衔接见[视频分镜提示词](references/two-round-delivery.md#视频分镜提示词)。默认采用「拆分分镜」时，组长、镜数、提示词格式和校验按该技能执行。以下本技能的分镜参数、模板与校验器用于明确采用本技能写作或延续其既有版式的任务。

先读取同一任务的已核对清单，再处理用户最新更改；不同剧本任务不借用旧参数。

| 参数 | 解析 |
|---|---|
| 交付范围 | 收到范围与请求范围分开；完整单集不因长、多场景或“全文”被切成多集。多集保留原集号，只交付请求集/组 |
| 画幅 | 明确比例则规范化并沿用。用户明确授权代选画幅，或明确把未指定的制作参数交由模型决定时，可选合理比例并记录“授权代选”及理由；短剧无其他依据时选9:16竖屏。仅说“继续/连续完成”不等于代选授权。新任务既无比例又无此授权时，只问一次“请确认本次分镜需要哪种画幅：9:16竖屏、16:9横屏，还是其他比例？”并等待；同时可做不依赖画幅的原文/资产工作 |
| 时长 | 新任务默认15秒；明确要求30秒时改为30秒。同一任务续作用已核对模式。各模式逐镜限制见下表 |
| 质感 | 新任务默认写实短剧质感；高精度3d/高精3D/3D乙女游戏CG等明确同义选择归一为高精度3D。只有用户要求选择/比较且未选定时才追问 |
| 音轨 | 同一台词的中英配对只以英文发声、估时；中文留内部译文台账。未配对内容保留原语言 |
| 交付分支 | 默认通用 Markdown；明确 LibTV 时增加 CLI 导入包，保留已确认时长、画幅、质感和本地母版。仅生成包不等于远端导入，导入不等于生成图片或视频 |
| 交付轮次 | 新剧本分镜默认两轮。首轮交《人物场景道具提示词汇总》《站位图提示词》《图片回传清单》后等待尚缺的参考图；第二轮核对图片并交最终分镜。用户明确要求一次性交付、只做资产或已有续作约定时按其要求 |

只对影响人物身份、台词归属、源集界、关键因果或明确要求的参考资产的真实缺口提出具体问题。普通机位、受支持的光线、非剧情性外观细节可合理设定并记录依据。缺图时按两轮交付规则标出受影响的组，取得用户同意后可用文字补缺。

## 作业主流程

1. **保存与读源。** 按长文本参考保存原文快照，运行 [build_source_ledger.py](scripts/build_source_ledger.py)，分块实际读完已提供正文并审阅分类。索引不替代阅读，摘要不替代锁定文本；工具截断的部分需补读。记录已读、待判定及请求范围。
2. **建立理解与资产。** 记录角色/别名、地点、时间线、必要动作、道具、衣装伤势及角色信息来源。有误会/隐瞒/反转时区分事实、人物相信什么、观众此时可知什么。建立 `location_id` 与 `scene_instance_id`：同一场戏隔组返回，承接该实例最近有效末态；同地点在次日、回忆或非连续事件中重返，另建实例并按原文确定初态。固定地点结构与动态人物站位分开保存。人物、场景、道具的需求提取及生图提示词默认交给「资产提取2」`$script-visual-asset-compiler`，按[资产提取交接](references/two-round-delivery.md#人物场景道具资产提取)使用提取结果。
3. **选择本批。** 用精确源ID、必要前后文、有效入态、资产版本与前两镜组成资料包。每个入场段查明本实例的接续来源组/镜和状态版本，展开本组空间初态；前两镜用于剪辑检查，不能代替被隔开场戏的最近末态。小任务可在每轮内一次完成；长任务在完整音频单元或动作里程碑处选可核对的批次。可先形成场景节拍与揭示位置的紧凑计划，但不改剧情、不把提纲当成品。
4. **依据状态编排镜头。** 先按[起草前的状态流程](references/full-script-mode.md#起草前先建立状态与必要变化再编排镜头)确定本段初态和必要变化，检查动作可达性与容量，再设计机位。读每段对话前后的画面描述，按[动作与对话时序匹配](references/source-text-and-shot-rules.md#3c-剧本动作与人物对话时序匹配)判定“先做再说 / 边做边说 / 说完再做”，混合情况分段判断；据此计算主声轨与动作的实际时间，再决定不等长镜头并写明动作、发声和反馈的先后关系。按[分镜使用规则](references/source-text-and-shot-rules.md#5e-分镜使用规则)选择单人、过肩正反打或多人站位关系镜头，优先给说话者单人镜头，并服从主体轮换。每镜解决一个主要可见任务；优先减少无剧情作用的走位、共持和反复换手，保留必要动作及其完成结果。长台词拆镜要推进不同可见节拍，不能只是重复同一画面。世界位置和原有动作路径约束机位、画幅、焦点轮换。
   - **首轮交付。** 默认先锁组界、时长、原台词和必要动作，保存内部结构与起始站位。交齐三份首轮材料。已有图片经逐张核对可计入清单，仅等待尚缺的参考图。
   - **第二轮续作。** 逐张查看并绑定已给和后续回传的参考图，核对身份、服装、场景、道具与各组入态。已有站位成图时，按[两轮交付](references/two-round-delivery.md#第二轮)直接在原图上逐人加红色矩形框，框内写红字姓名，再核对身份。齐图或用户同意文字补缺后，沿用已确认的结构进入第5步。
5. **锁定并细化。** 确认时间、镜数、组界、台词节奏和动作里程碑，两轮流程沿用首轮底稿。第二轮按已核对图片修订形象、场景、道具和起始站位，逐组填入参考图片，再按可读面部、时长容量与情绪事件细化表演和光色。表情模块不得改时长。若表情本身是原文剧情事件，回到编排层解决后重新锁定。
6. **核对实际成品。** 运行 [verify_storyboard.py](scripts/verify_storyboard.py) 核对快照、分类与最终 Markdown 音频字段及组内秒数加总。另做必需动作、知情/揭示、资产、空间、表演、格式与相邻镜头复核；按镜头复核的 Audit 2B 检查每次位置、姿态、视线、持物与接触变化的依据、承载镜和结果，并逐条检查同实例接续关系，包括不相邻组。主体简表、组头初态、逐镜动作与下组入口须一致，缺少过程或容量不足时回到编排层修复。进入已授权媒体制作时，按全局资产管控第3A节检查本组首帧、实际视频及参考绑定。分别记录文字计划与实际画面核对结果；程序通过或重复强调站位不能代替语义与视频效果验证。
   - 回传人物站位图参与返修时，执行[站位图返修与画布视频节点导入](references/two-round-delivery.md#站位图返修与画布视频节点导入)。逐组反复复核将要写入的实际提示词，达到可投入 AI 视频生成的工业级定稿标准后，再按本轮授权写入画布视频节点。
7. **保存并继续。** 保存本批产物、检查报告、源范围、有效末态、依赖修订和下一源单元；继续全部请求范围。最后对实际汇编文件重新核对，交付文件和简短范围说明。最终交付全剧提示词时，同时交付一份独立的“人物场景道具提示词汇总”，按最终实际使用的资产及版本整理完整可复制正文，并核对覆盖与一致性，详见全局资产管控第6节。只因真实输入缺口或执行限制未完成时，准确记录未完成范围与续作点。

用户要求同步飞书或当前项目已有适用的授权绑定时，在本地资产核对后继续[飞书 Base 资产交付](references/lark-base-asset-delivery.md)。本地全剧提示词与独立汇总仍按原要求交付；飞书同步完成需另有读回证据。仅安装或修改技能、收到参考模板链接不自动建立写入授权，也不创建定时同步。

用户指定 LibTV 时，在实际分镜核对后继续 [LibTV CLI 分支](references/libtv-cli-delivery.md)，从同一成品派生分镜行，不让平台重新改写剧本。运行 [verify_libtv_handoff.py](scripts/verify_libtv_handoff.py) 比较导入包与本次 Markdown 的镜头顺序、时长和对白，再核对镜首状态与动作时序。LibTV 是交付适配分支，不放宽制作契约，也不替代全剧人物场景道具提示词汇总。

源文台账与通用分镜校验的脚本命令、JSON schema、选集与跨批核对边界以长文本参考为唯一接口说明；平台交付接口见相应分支参考。`--structure-only` 不表示分类已复核，`--ledger-only` 不表示成品通过。源文未知项不能批量标成已复核；失败不能靠改原文、缩范围或假映射消除。

## 制作契约摘要

完整规则在镜头契约及对应参考中；这里列出不可因模型升级自行放宽的要求。

| 模式 | 完整组总时长 | 单镜上限 |
|---|---|---|
| 15秒 | 默认14.5–15.5秒 | 3.5秒 |
| 30秒 | 默认29.5–30.5秒 | 5.0秒 |

- 按发声原语言估时并计入停顿；先后阶段相加，重叠区间只计一次，保留未重叠的前后部分，一条活动完全覆盖另一条时才直接取较长需求。小于2.5秒的镜头必须有自然匹配的短源台词；静默短镜并入相邻动作。每集最后不足一组可保留真实短尾；不跨集借台词、不编动作凑时。
- 台词、VO、旁白、重复出现的台词均按各自源位置逐字保留；拆句保留原标点、词间空格与顺序。字幕标记和双语译文只入内部台账。每镜一个音频字段，每行有声内容保留源说话者；无声写“无”。
- 普通组以中景、关系和动作镜头为主，近景/面部特写合计不超过镜数一半；出场、揭示、情绪关键节点按原规则记录比例例外。三镜滚动窗口避免同一焦点角色连续占据三镜；真实单角色场景保留主体轮换豁免。组内相邻镜默认使用不同标准景别；换人物、明显换角度、真实过肩正反打、人物独处或源文支持的情绪高潮可豁免，但仅小幅角度变化不构成豁免。逐对记录依据，具体判定见源文与镜头第5B节；非相邻镜头可复用景别。跨组末/首镜仍必须不同，不沿用组内豁免。修复要复查前后相邻镜、重叠主体窗口与跨组边界，不能牺牲源文与完整动作。
- 恰好1名可见角色为单人镜头，2名及以上为关系镜头；过肩正反打沿用单人镜头的主体、站位和说话情绪规则。“多人站位关系镜头”至少3名可见角色，在单人/过肩方案无法兼顾主体轮换与必要动作、人物大幅度动作或站位调度时使用。说话情绪用源文支持且符合时长的可见表现与声音强化；关系镜头仍按真实焦点检查轮换，不能仅靠增加同框人数通过。
- 单可见角色只用“画面简介”，以标准景别、基础角度、简单运镜、焦点开头，分号后写背景/位置/动作。2名及以上可见角色（包括前景肩背）或道具细节采用“镜头与人物的位置关系 → 镜头机位 → 画面简介”；唯一中心锚点，道具镜角色标画外。过肩正反打沿用单人设计规则，不改变按可见人数选字段的规则。
- 内部分析服务可见结果；每组初态按整本模式第3节展开固定参照、人物物理位置/朝向/视线/姿态、距离关系、持物与拍摄侧，写入实际主体/场景/镜头文字。首镜从该初态起步，动作完成镜写清结果，按实际镜头保存有效末态；换焦点与机位不重排人物。成品不用“同上/继承上一组”、内部ID或不存在的图片代替可用内容；资产卡的白底站姿不进入剧情镜头。
- 使用固定集标题、七项全局连续性、组标题、必需字段和镜头块；每组`主要主体`按“人物 → 场景 → 道具”简写，文字资产用服饰简述，第二轮已核对的图用资产 ID 和当前状态，完整规范见[交付格式](references/final-delivery-format.md#主要主体人物场景道具简表)。每组以“负面提示词：”结束。高精度3D正向英文块每组恰好一次，负向块逐字保留；不用字幕、BGM或工作流分析污染正向提示词。

## 并行与修订

工具支持且能节省时间时，把独立的资产清单、原文分类复核、语义复核或已知边界的独立场景交给子代理。子任务只提供必要原文、任务契约、已验证状态和输出位置。短任务无需为了形式拆代理。

主模型持有规范版本；子代理返回源ID、发现/产物、依赖版本和不确定项，不直接覆盖共同台账。连续场景的上下游先确定交接状态；下游使用暂定状态时保持“已起草”，待上游核对再复核。并行上限和模型选择服从当前运行环境，不硬编码未提供的工具、模型或API功能。

生成提示词按[整本模式的执行输入编译](references/full-script-mode.md#从状态底稿编译执行输入)展开当前段所需事实。只交文字时可完成计划状态核对；图像、视频和生成任务检查按实际请求阶段执行，不因缺少制作授权而阻塞独立的文字交付。

修订按 [叙事证据与依赖](references/narrative-evidence-and-state.md) 定位影响：源文改变重建修订和片段映射；持物手、资产几何、人物知情等更改传播到实际消费者。只重审受影响成品，旧报告保留但不能代表新版本。没有新的改动、失败或未决问题时，不重复整套检查。
